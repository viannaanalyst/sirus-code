# Architecture reference

A detailed map of how Sirus Code is built today: modules, domain, IPC, providers, Git, security choices, design system and performance. It describes the code as it is, to save rediscovering it; it is a reference, not a rulebook. When the code and this page disagree, the code wins, and this page should be updated.

Contributor basics live in [`AGENTS.md`](../../AGENTS.md). Decision history lives in [`docs/decisions/`](../decisions/README.md).

| Primitives | Radix + vendored UI Arc MIT components through existing primitives |
| Motion | `motion` (Motion for React) + CSS tokens |
| Diagrams | `mermaid` (lazy, strict, ADR-058) for fenced `mermaid` blocks |
| Icons | Phosphor (`@phosphor-icons/react`) through `src/components/icons/phosphor.tsx`; filled weight marks active items |
| State | Zustand (`src/store/app-store.ts`) — do not add another store |
| Native | Rust 2021 edition, crate `sirus-code` / lib `sirus_code_lib`; features `desktop` (default, Tauri app) and `host` (headless `sirus-host`, ADR-131) |
| Git | Git CLI argv + worktrees |
| Terminal | portable-pty + `@xterm/xterm` |
| Persistence | SQLite `state.db` (one row per message, ADR-114); the older JSON files are only the migration source and fallback |

No Next.js. No Electron. No app login.

## Architecture (current)

```
React UI (src/)
  → SirusClient (src/client/index.ts)
    → Transport (src/client/transport.ts)
      → LocalTransport (src/client/local-transport.ts)  # Tauri invoke/listen
      → SwitchingTransport (src/client/switching-transport.ts) # phone and desktop: follows the active computer (ADR-132, ADR-133)
        → RemoteTransport (src/client/remote-transport.ts) # another device: WebSocket to remote.rs (ADR-080), one per computer
        → Tauri IPC
          → Rust commands (src-tauri/src/commands.rs + lib.rs pick_folder)
```

**UI must not import `@tauri-apps/api` except inside `LocalTransport`.** The UI served to another device uses `RemoteTransport` (ADR-080) for the same Client API; `isRemoteUi` tells the two apart. A phone may know several computers (ADR-132): `lib/environments.ts` keeps the list (the page's own origin is `home`, its token under `REMOTE_TOKEN_KEY`), `client` sits on a `SwitchingTransport` over the active computer's `RemoteTransport` (`switchEnvironment` moves calls and listeners), and `store/environments-store.ts` watches the other computers through `environmentClient(id)` for cached summaries that the merged Home, Choose project and Projects read (`components/mobile/MobileEnvironments.tsx`). Row actions for a computer out of reach wait in `sirus.environments.pending` (`queueRowAction`, flushed in order when it answers); Archived and Snoozed list every computer with a computer filter. The desktop app does the same (ADR-133): its `SwitchingTransport` starts on `LocalTransport` (this Mac, `home`) and moves to a paired host's `RemoteTransport`, while window-bound commands and events (`lib/computers.ts` `runsOnThisMac` / `eventFromThisMac`: remote access, pickers, dictation, browser, devices, window snap…) stay on `LocalTransport`; `localClient` always talks to this Mac. A remote command that gets no reply fails after 2 minutes (15 for long ones such as `send_prompt`, clone, push or provider updates; `invokeTimeout` in `remote-transport.ts`), so a silent socket never hangs the UI. Switching computers clears what belonged to the one left (queues, tabs, dock panes, terminals, split layout, history, usage, models, inbox; `resetComputerScope` in `app-store.ts`) before the next one bootstraps. `store/computers-store.ts` keeps the desktop's computers (Settings → Connections → `ComputersSettings.tsx`), watches the others for the project switcher (`components/ComputerSwitcher.tsx`) and runs "Move to" (`components/MoveSessionDialog.tsx`).

Trust boundary: the webview is untrusted. Rust validates every path and every process spawn.

## Domain (as implemented)

- **Project** — user-added folder. `remove_project` drops metadata and sessions, **not** files on disk. Optional `look` (colour, emoji, logo, Astro icon or line icon; ADR-059, ADR-116) changes only its sidebar icon. Optional `scripts` (`setup`, `onFinish`; ADR-078) run in its sessions' isolated worktrees.
- **Session** — `idle | starting | running | waiting | completed | failed | stopped`. Owns `agent` (provider), optional `model` (CLI model id), `worktree`, `messages`, `lastError`, and last-admitted `execution` preferences (effort/Fast/planning/approval). Codex, Claude and OpenCode persist an exact `nativeThread` bound to session/project/canonical cwd/model; `pendingRequests` are live-generation-only and are never restored from disk. A coordinator may own a `team` (plan, tasks, merge state) and its helper sessions carry `teamWorker`. A side chat carries `sideChat.parentSessionId`. `scripts` holds `setupPending` (a new isolated worktree owes its Setup run) and the latest project script run of each kind (ADR-078). `snoozedUntil` hides a settled session from tabs and lists until the native timer brings it back, and `snoozeReminderAt` keeps it unread until it is opened (ADR-103). In the header switcher it waits under a collapsible "Snoozed (N)" group with a moon, a live countdown, Return now and Change time; "Snooze…" in the switcher row and tab menus opens a picker with 1 hour, 3 hours, Tomorrow at 9 AM, Next Monday at 9 AM and a date and time, and snoozing raises an Undo toast.

**Team** (ADR-043) is a one-shot `+` → Equipe composer mode. The coordinator runs a read-only planning turn and returns at most 3 validated tasks, each with an assignee, planned paths and an optional earlier dependency. Nothing runs before the person confirms; edits are limited to titles, assignees and removing tasks. Each task becomes a normal session in its own isolated worktree. The worktree starts from a private snapshot commit of the coordinator checkout as it is now (uncommitted and untracked non-ignored files included; the person's index and files untouched), and each task runs using the person's Ask/Auto policy (never Full). Approvals stay with the person. A dependent starts only after its prerequisite succeeds. "Merge all" is explicit:

- it applies each finished task to the coordinator working copy in plan order, with no commits;
- before applying, it checks planned paths, then runs `git apply --check` against the current files;
- it stops at the first conflict without applying that task, offering skip, merge anyway (only for out-of-area changes) or Resolve with AI (only for conflicts). Resolve three-way-merges the current checkout snapshot into the helper's own worktree; leftover conflicts go back to that helper for one turn. Patches that still contain conflict markers are refused.

Cleanup of helper worktrees is confirmed; it first commits each helper's remaining edits to its own branch so worktrees are removed without force and nothing is lost. Helpers nest under the coordinator in the sidebar.
- **GitWorktree inventory** — real porcelain `-z` entries with path, HEAD, branch, detached/bare state, lock and prunable reasons.
- **Worktree** — `{ path, branch, isolated }`. Isolated trees live under app-data `worktrees/{projectId}/` with branch `sirus/<slug>-<id>`. Non-isolated uses the project checkout.
- **AgentProviderId** — `codex` | `claude` | `opencode` | `cursor` | `grok` | `antigravity` | `droid` | `pi` | `devin`. Session is an **agent** process; Settings lists **Providers** (the CLIs). Do not name the Settings section “Agents”.
- **Message** — user | agent | system; `streaming` flag. Agent replies may hold `visuals` (`id`, `title`, `html`, `createdAt`, `revision`; ADR-123), stored in the message's row; rows without the field load as before. New native assistant responses optionally retain `activity` with per-turn provider/model, native timing and at most 128 observed tools/children. Rows keep a bounded `detail` and the reply `offset` where they began; the transcript interleaves text and work in that order, groups back-to-back rows into one sentence, shows the running step live and folds a finished turn behind "Worked for …" ([ADR-070](../decisions/ADR-070-turn-timeline.md)); subagents show as cards with a state pill that open into their own steps. Children keep their native time window and up to 20 newest generic steps (400 per turn); no tool output, reasoning or child control. See [ADR-035](../decisions/ADR-035-native-turn-activity.md).
- **GitStatus / FileChange** — real `git status` / `diff`; never invent clean/dirty.
- **AppSettings** — `defaultAgent`, `defaultModel` (`provider::id`), `modelExecution` (qualified preferences), `openLastProject`, `disabledProviders`, `favoriteModels` (retained `disabledModels` is ignored: every model of an enabled provider is offered), `sidebarCollapsed`, `sidebarProjectOrder`, `sidebarProjectSortOrder`, `sidebarThreadSortOrder`, `sidebarAttentionFirst` (working, waiting and unread sessions first, off by default; ADR-121), `pinnedProjectIds`, `pinnedSessionIds`, `archivedSessionIds`, `environmentPanelDefaultOpen`, `showEnvironmentUsage`, `showEnvironmentRepository`, `showEnvironmentEditor`, `showEnvironmentPullRequest`, `showEnvironmentPinned`, `showEnvironmentNotepad`, `showEnvironmentInstructions`, `enableProviderUpdateChecks`, `locale`, `customShortcuts`, `uiFontSize`, `confirmCloseRunning`, `restorePreviousSessions`, `developerLogs`, `computerUseEnabled`, `sidebarUsageProviders` (at most two providers that report usage, validated natively), `windowSnapEnabled` / `windowSnapShortcut` (closed presets, ADR-054), `steerWhileRunning` (ADR-062), `ciAutoFix` (ADR-064), Chat behavior (`dictationEnterSends`, `foldFinishedTurns`, `githubLinksInApp`, `diffWordWrap`, `confirmArchive`, `confirmTerminalClose`), `githubPins` (≤200 `owner/repo#n`), `railItemOrder` / `hiddenRailItems` (closed rail IDs, Home never hidden) / `railProjectShortcuts` (≤12), optional `worktreeBasePath`, `releaseWorktreeOnArchive` (ADR-078, off by default), `chatBackground`, `chatBackgroundEffect`, `chatBackgroundShowOn`, `chatBackgroundEmptyVisibility` / `chatBackgroundSessionVisibility` (ADR-089). A retained `profile`, `prWatch` from the removed Profile page is ignored, and so are `sidebarActivityView` and `doneSessions` from the removed Activity view (dropped on the next save).

Unsent composer drafts are owner-validated `project:<id>` / `session:<id>` keys in native `AppData`. Edits checkpoint at most every 250 ms, driven by incoming edits; shutdown saves the latest admitted edit. Metadata removal prunes its drafts. Restored content is never sent automatically. Unsent attachment metadata/goal edits/planning/debugging and provider-specific approval selections are memory-only owner-scoped context in the existing store; native selection/paste supplies bounded private file copies (8 files, 10 MiB each, 40 MiB per turn) or shallow folder names. The header exposes the Environment card and the right-dock toggle. The right dock replaces the old segmented Context panel: it is a full-height column beside the chat (its own top row aligns with the window header and shares the chat surface color), an empty dock lists Terminal, Files, Changes, Browser, Side chat and Simulator (ADR-128: Expo's device hub behind a consented install; device picker, live touchable screen decoded with WebCodecs or MJPEG, hardware keyboard, Home/Lock/Rotate, appearance, Open URL and Shut down; the stream runs only while the pane is shown; it replaces ADR-066's native helper, removed on 2026-10-08), panes become pill tabs (icon that turns into a drag grip on hover, name, close; they shrink to fit and reorder by dragging through `moveDockPane`; Changes and Editor are reachable from the Environment card and file clicks), and the dock can be collapsed, maximized or resized. Every terminal has an independent PTY; terminal identity is the terminal id, not the session, region or tab id. The store's `runningTerminals` (`src/lib/terminal-running.ts`) follows PTY start, `pty-exit` and disposal, never polling; a session with a running terminal shows a terminal glyph in its switcher row and header tab, and clicking it selects the session and shows that terminal in the dock's Terminal pane without starting another (`revealTerminal`, ADR-121). Right-clicking the dock's tab strip offers Close panel and Close all tabs: every tab the strip shows closes right to left, so ⇧⌘T puts each back in place; it asks once before discarding unsaved editor files, leaves files still saving open, and does not ask about terminals, whose shells outlive their tab (`src/lib/dock-close-all.ts`). Terminal OSC 8 hyperlinks go through xterm's `linkHandler`, http(s) only (`src/lib/terminal-links.ts`), and open like detected addresses: click in the session browser, ⌘-click in the system browser.

To add a provider:

1. `AgentProviderId` in Rust **and** TypeScript.
2. `detect.rs` binary name.
3. argv in `agent.rs`.
4. `src/lib/provider-registry.ts` metadata/capabilities and provider asset.
5. Catalog strategy in `provider_models.rs` and stream decoding in `agent_output.rs`.

Do not store vendor tokens. Use the CLI’s own login. Owner-authorized named Codex/Claude accounts may start fixed vendor login in a new private profile; never replace the default or a profile already used by sessions, copy tokens or accept auth material through IPC. Login output is discarded, bounded and secret-free; cancel/shutdown kills owned groups. Cursor/OpenCode named login is unavailable. No account removal or logout command. See ADR-015.

Current argv (verify in `agent.rs` before documenting a change):

Environment and header values never cross IPC; the UI shows `KEY=••••`. Add server accepts pasted `mcpServers` JSON or a form and writes each chosen provider's own shape; remove deletes one entry. Every write keeps `<file>.sirus-backup`, preserves all other fields (Codex comments and layout too), refuses unreadable files and replaces the file atomically with its permissions (new files 0600). JSON files are re-serialized, so their key order may change. `/mcp` in the composer shows the servers available to the session's provider. Provider account profiles (`CLAUDE_CONFIG_DIR`, per-account `CODEX_HOME`) are not read.

With Settings → MCP servers → "Let agents manage sessions" on (`agentsManageSessions`, default off; ADR-076), the `--mcp-browser` child of every Codex/Claude/OpenCode session also lists `sirus_list_sessions`, `sirus_read_session`, `sirus_session_status`, `sirus_create_session` and `sirus_send_to_session`. They see every project and every session except side chats; reads are bounded (≤40 rows, ≤20 messages of ≤2,000 characters). Starting and messaging reuse the shared launch path (`launch.rs`): new turns carry the caller's approval mode, a planning caller is refused, a session cannot message itself or a busy one, one caller turn may start 4 sessions and send 8 messages, and sessions started by agents may nest only two levels. Agents cannot delete, archive, rename or stop sessions, answer approvals or change settings through these tools.

**Inline visuals** (ADR-123): the always-on `sirus_show_visual` tool takes a title and one self-contained HTML document (≤512 KiB) and adds it to the calling session's current reply (the agent message after its latest user message), or replaces the visual with the same title in that reply. The bridge and stdio child accept lines up to 4 MiB to fit an escaped page. The reply renders each visual as a card (title, Copy source) with the page in a frame:

- **Frame.** `<iframe sandbox="allow-scripts" src="sirus-preview://localhost/v/<id>">`: no `allow-same-origin` (opaque origin, no app storage, cookies or IPC), no `allow-top-navigation*`, `allow-popups`, `allow-forms` or `allow-modals`. `srcdoc` is not used because it would inherit the app CSP (`script-src 'self'`), which blocks inline scripts; the custom scheme lets the page carry its own policy. The document is registered with `html_preview` (content-hashed, memory only, ≤48 pages) and its URL holds no token.
- **CSP** (`VISUAL_CSP`, sent as a header): `default-src 'none'`; scripts `'unsafe-inline' 'unsafe-eval' https:`; styles `'unsafe-inline' https:`; images, fonts and media from `data:`/`blob:`/`https:`; `connect-src`, `frame-src`, `child-src`, `worker-src`, `object-src`, `manifest-src` `'none'`; `base-uri 'none'`; `form-action 'none'`; plus `Referrer-Policy: no-referrer`. A page cannot read any response from the network (fetch, XHR, WebSockets, EventSource); the bridge also removes the WebRTC constructors, which CSP does not cover. Public https subresources (a chart library, a web font, images) load; a page could leak data it holds through an image URL, but it holds nothing but what the agent wrote and the theme, and the agent already has network access. Navigating the frame elsewhere is blocked by the app's `frame-src sirus-preview:`.
- **Bridge.** The front end builds the document as `<!doctype html>`, the theme as `--sirus-*` variables (names and values allowlisted, no `;{}<>` so a value cannot leave its declaration), zero-specificity base styles, the bridge script, then the agent's HTML unchanged. The bridge reports the content height (the frame clamps it to 48–640 px and taller pages scroll inside), turns trusted link clicks into a request, forwards wheel gestures the page cannot scroll itself so the transcript keeps scrolling, and applies theme messages only from `parent` (setting `data-theme`, `color-scheme` and firing `sirus-theme`). The app reads messages only from that frame's window, validates every field (`readVisualMessage`), and opens links only for absolute http(s)/mailto URLs, only while the frame has focus (the person clicked into it) and at most once a second, through the existing `openLink` → `open_external_url` path.

**Guided reviews** (ADR-125): the always-on `sirus_write_review_guide` stores a step-by-step tour of a pull request (`pullRequest` as `owner/repo#123` or its link) or of the caller's own uncommitted changes, replacing the earlier guide for that target; `sirus_read_review_guide` returns one. They only write the guide, never code, so planning callers may use them. Input is validated with reasons the agent can act on (one-line titles, Markdown ≤4,000 characters, repository-relative paths without `..`, lines from 1, ≤400 lines per anchor, ≤24 steps, ≤8 anchors, hex `headSha`).

The same bridge carries private secret requests (ADR-077). `request_secret` (label, description, optional `envName` and workspace `path`) blocks up to 5 minutes while a private card above the composer asks for the value; Provide sends it over `secret_action` into native memory only and the agent receives a one-use `secretRef`, never the value. `use_secret` spends it once: `file` writes it to the path shown on the card (dotenv line when `envName` is set; untracked, inside the workspace, `0600` when created), `env` writes a `0600` export file in the private `secrets/` folder to source for one command in the provider's own shell. References, values, cards and env files die at turn settlement and quit; live values are scrubbed from output; the transcript shows only "Secret provided (label)". Codex receives `tool_timeout_sec = 330` for the bridge.

Computer use (ADR-038) is off by default. When `computerUseEnabled` is on, Codex/Claude/OpenCode turns receive the app-owned `sirus_computer` MCP server (nine fixed tools, actions return the settled observation). Every app needs an in-session approval per session (memory-only); password managers, Keychain, System Settings, terminals, automation tools and Sirus Code are always blocked; planning is read-only; physical Escape or the floating pill's Stop revokes all grants. Input is Accessibility-first and posted to the target process; only `computer_focus` brings an app forward, after 1.5 s without human input. Accessibility and Screen Recording are requested only through fixed native prompts/panes.

Quota reads use Codex app-server and Claude's experimental native `get_usage`, without inference. The owner authorized a narrow credential-reading exception for Cursor and OpenCode Go: Rust reads only the existing Cursor CLI access token (one exact Keychain item on macOS; the CLI auth file elsewhere) and the existing `opencode-go` API key. Three fixed HTTPS GET endpoints return quota/account metadata; redirects, retries, proxies, browser-cookie/SQLite readers, credential enumeration and login/token refresh are unavailable. No renderer-selected URL, headers, auth data or file paths. Raw credentials/responses never cross IPC, logs or persistence. Account email/name/plan and a short non-secret key fingerprint may be displayed; Go exposes no email. HTTP cache entries bind executable and native credential digest, revalidated before publishing. See [ADR-014](../decisions/ADR-014-scoped-authenticated-quota-reads.md).

Provider CLI update checks cover only Codex (`@openai/codex`), Claude (`@anthropic-ai/claude-code`) and OpenCode (`opencode-ai`) npm versions; Cursor/Grok stay unchecked. npm-managed installs update through fixed npm argv, a natively installed Claude Code through its own `update` subcommand and a script-installed OpenCode (`~/.opencode/bin`) through `opencode upgrade --method curl`; anything else reports `updateSupported: false` with a manual-update note. `AppSettings.enableProviderUpdateChecks` gates the check, the persistent toast offers Review updates and Update all, and updates are always an explicit user action. See [ADR-020](../decisions/ADR-020-provider-cli-update-checks.md).

`AppSettings.sidebarUsageProviders` persists the sidebar quota rings (retained `usageProviders` from the removed footer is ignored); snapshots, account metadata and offers remain memory-only. No polling. The composer's plan-usage chips (ADR-120, `ComposerUsageChips` + `lib/composer-usage-chips.ts`) show the session provider's 5-hour and weekly (or monthly) windows from the same `usageByProvider` store: one unforced read when the provider has none yet, then the existing refreshes (a finished turn also refreshes a provider whose usage is already loaded); hidden without a reading. `consume_codex_reset` is the sole account-consumption exception: an explicitly confirmed, short-lived native offer, freshly matched CLI account email and named credit, once-only reservation and UUID idempotency key. No purchases, overage, plan/config/auth changes or automatic redemption/retries. Reset lifecycle rules remain in [ADR-013](../decisions/ADR-013-provider-usage-and-earned-resets.md).

## Worktrees and Git

- Isolated worktrees: [ADR-004](../decisions/ADR-004-git-argv-no-destructive-defaults.md).
- **Never** automatically: `reset --hard`, `clean -fd`, `worktree remove --force`, force-push.
- Delete isolated worktree only with `confirm: true`; removal then prunes worktree metadata and the emptied project folder. Settings → Worktrees cleans up confirmed leftover folders no session references, keeping anything dirty or unverifiable; branches are never deleted (ADR-078).
- **Project scripts** (ADR-078): owner-saved Setup runs in a new isolated worktree after the first turn is admitted and before the provider starts; On finish runs after each completed or failed turn. Both run as the person in the worktree, bounded, and never fail the turn; the latest run shows above the composer.
- Pull is an explicit, confirmed `git_workspace_action` (fast-forward only, never merge/rebase, Push's network-helper refusal); Create PR pushes then opens the PR through hardened `gh api` (ADR-065).
- Commit and Push are explicit user actions. Commit stages nothing by itself (existing staged changes only) and Push never forces. Hooks/filters guards apply to both. The one exception is owner-enabled CI auto-fix (ADR-064): after its own fix turn it stages only that turn's files, commits and pushes the session branch (never forced; refused when unrelated changes are staged).
- Native Git runs with `GIT_OPTIONAL_LOCKS=0` so polling never takes `.git/index.lock` from an agent; `git::status` counts lines with plumbing `diff-index` and lists at most 2000 untracked files (`untrackedTruncated`, ADR-100).
- Session always knows project, branch, worktree path, agent.

## Security

Treat project contents as untrusted.

- Canonicalize paths. Isolated session cwd is the worktree dir; non-isolated must stay under the project root (`session_cwd` in `commands.rs`).
- No path traversal, no shell strings for Git/agents. Native Git disables filesystem hooks/fsmonitor, refuses configured `hook.*` entries (Git 2.54 ignores hooksPath for those), and refuses affected operations when external checkout filters are configured. Inspectors and operations remove the config-only `GIT_CONFIG` override consistently; hook/filter inspection is names-only, output-bounded and deadline-bounded. These are preflight guards with a concurrent external-config-change limitation, not an OS sandbox. Never silently replace LFS/filter semantics. Automatic fetch remains unavailable until networking and ref import are config-isolated.
- PTY binary is not chosen by the UI ([ADR-007](../decisions/ADR-007-pty-is-user-shell-only.md)).
- Branch switch/create are explicit actions (`confirm: true`), validated against real local branches (charset + `check-ref-format`), and reuse the same hooks/filters guards as every other native Git command.
- Sidebar project rows show the checkout's uncommitted `+N -M` (`project_diff_stats` → `git::diff_totals`): tracked changes against HEAD plus the lines of up to 500 new text files (≤ 1 MiB each, binaries and links count as nothing). It is refreshed after a turn settles, after Git status refreshes (selection, commit, push) and on window focus, never on a timer.
- Push refuses project-local network helpers (`credential.*`, `core.sshCommand`, `core.gitProxy`, `core.askPass`, `remote.*.uploadpack/receivepack/proxy`, `url.*.insteadOf`, `http*.proxy`) because they can redirect credentials or connections.
- Editor files: read/overwrite only existing regular files inside the session cwd; `.git` paths are refused; 2 MiB read / 1 MiB write; opens use `O_NOFOLLOW` and re-verify the opened descriptor, and content is truncated only after verification.
- External links: http(s) only, no credentials in the URL, fixed host allowlist (`localhost`, `127.0.0.1`, `::1`, `github.com`). The GitHub URL is derived in Rust from `origin`, never rendered by the renderer.
- Provider updates: `provider_updates` reads only `registry.npmjs.org/<fixed first-party package>/latest` (no redirects/retries, bounded body, six-hour memory cache, no polling); `update_providers` requires `confirm: true`, validates ids against the native package map and runs a fixed `npm install -g` argv with bounded output/timeout. No renderer-supplied package, version, URL or flag.
- Provider conversation import was removed (ADR-021 superseded). Previously imported sessions keep `importOrigin` only for compatibility.
- CSP in `tauri.conf.json`. Do not load privileged remote content. `connect-src`/`img-src` allow `http://127.0.0.1:*` and `ws://127.0.0.1:*` only for the Simulator pane's token-checked loopback proxy (ADR-128).
- Reply media (ADR-119): the renderer never names a file to the `sirus-media` scheme; it asks `reply_media` for a token, and Rust grants one only to an image that passes the reply-image rule (extension, regular file ≤ 25 MiB, image bytes) or a video inside the session workspace after canonicalization. The scheme serves token holders only; the asset protocol stays closed.
- Agent HTML (ADR-072 previews, ADR-123 inline visuals) only runs on the `sirus-preview://` scheme in a frame without `allow-same-origin`, under its own CSP with `connect-src 'none'`; messages from those frames are validated per field and links leave only as http(s)/mailto through `open_external_url`.
- Dictation is native macOS only (ADR-027): one process-wide session, fixed locale pair, bounded 300 s capture into a private temp `.caf`, transcribed once on stop with `DictationTranscriber` (punctuation, short-form) and deleted; `stop_dictation` returns the transcript and there are no `dictation` events; `Info.plist` carries the microphone/speech usage strings; the app binary needs the `/usr/lib/swift` rpath for the Swift bridge. No WebView speech APIs.
- Git runs from a fixed real binary (`/opt/homebrew/bin/git`, `/usr/local/bin/git`) before the `/usr/bin/git` shim, whose cold `xcrun` lookup can exceed the 4 s config-inspection bound (`git::git_binary`).
- Do not log tokens. Do not auto-run commands suggested by agent output.
- Prompt links (ADR-122) are untrusted input: `prompt_link.rs` accepts only `sirus://new` with the six known parameters, each once and bounded (128 KiB link, 8,000-character prompt), a known provider id and a `valid_model` model; it strips C0/C1 controls, zero-width, bidi, tag and filler characters and the UI warns until dismissed when any were removed. A link only fills the landing's draft; it never sends, and cannot set approval, branch or worktree. The renderer has no `deep-link:` permission, and `take_prompt_link` is refused over remote access.
- Remote access (ADR-080) is off by default and answers only loopback and Tailscale peers; a device token grants what the window can do, so `remote_*`, pickers, dictation, computer use, the embedded browser (`browser_*`) and `plugin:` commands are refused over the socket and only token hashes are stored. The headless host (ADR-131) keeps these rules, listens on one address (its Tailscale IP by default, never every address unless asked) and still requires a device token on every API and WebSocket route whatever the peer. Cross-origin requests (ADR-132) are refused unless the origin is an HTTPS `*.ts.net` name on the same tailnet, and reach routes other than pairing and health only when that origin was recorded with a paired device. The desktop app's own page (`tauri://localhost`, `http(s)://tauri.localhost`, exact matches) is treated the same way (ADR-133).
- Credentials are masked (`redact.rs` / `src/lib/redact.ts`, ADR-077): activity detail and command output before storage, approval-card commands, reasons, diffs and tool input at display. Secrets requested by agents never touch disk except the file the person approved or a turn-scoped private env file.
- Changes to IPC, FS, PTY, process spawn, or credentials need a security pass before “done”.

## Design system

Quiet at rest. Responsive in motion.

Reuse primitives before adding CSS. Arc integration and provenance: [`docs/development/ui-arc.md`](../development/ui-arc.md). The HTML declares CSS layer order before shared/lazy chunks. Tokens in `src/styles/index.css` (`--background-0`…`--accent`, `--motion-*`). No random hex, no random durations. Product typography uses the shared `ui-*` role utilities (titles, sections, controls, descriptions, captions, body/chat) in `src/styles/index.css`; role sizes follow `--ui-font-scale`. Do not choose independent font sizes in product components. See the [typography role table](../development/ui-arc.md#product-typography).

Launch has no splash (ADR-098): the main window is created hidden, Rust applies its appearance (glass or opaque) and shows it when the front end calls `window_ready` on its first ready paint (`src/lib/window-opening.ts`), or after a 2.5 s native fallback. The content is then wiped in from the left edge (`clip-path`, 550 ms) while the rail, header and main area slide in from the left (`src/styles/opening.css`, `html[data-opening]`); reduced motion gets a 150 ms fade. Settings is revealed by a circle from the rail's Settings gear and folds back into it; menu content enters from the direction of travel and the selection highlight glides between items.

**Popup rules** (every new popup follows them):

- **No instant mount or unmount.** Nothing floating may appear or vanish instantly; keep it mounted through its exit, with `AnimatePresence`, Radix `data-state="closed"` keyframes, or a delayed clear such as `afterToastExit`.
- **Dialogs:** rise 10px and grow from 95% on a light spring (about 0.28 s), with the overlay fading in alongside. They leave in about 0.15 s.
- **Menus, dropdowns, popovers and hover cards:** grow from 96% from their anchor or pointer in about 0.14–0.16 s, and leave in about 0.08–0.11 s.
- **One entrance (ADR-096):** popup boxes carry `data-popup` and enter on the shared `popup-in` keyframe (opacity and `scale` 0.96→1, `--motion-popup` 160 ms, `--ease-out`, from the Radix transform origin). They leave on `popup-out`, a `--motion-popup-exit` 100 ms fade. Use keyframes on `[data-state]`, not `@starting-style` transitions: Radix holds keyframes until the panel is positioned, while a transition runs off-screen and is mostly spent before the first paint in WebKit. Rows then cascade like the sidebar did (`cascade-in`: fade and `translate: -10px 0`, `--motion-slow`, 22 ms steps after the 40 ms `--cascade-lead`, capped at ten steps). Inside `[data-cascade]`, mark rows `data-cascade-item` with `cascadeIndex(i)`, or use `data-cascade="children"` to stagger direct children by position. Menus always cascade. Popovers opt in through `useCascade(open)` (`src/lib/cascade.ts`), which keeps the attribute for 640 ms after opening, so rows mounted later (search results, late data) just appear. Exits never cascade. Animations off, Reduce motion and `prefers-reduced-motion` turn the cascade off; the system setting leaves a plain fade on the box.
- **Toasts:** they stack top-center and all share the same entrance and exit.
- **Menu style:** a real icon in every action item, never the "···" placeholder. Groups are separated by a rule (ContextMenu `group`), and destructive items sit last in red. Shortcuts are shown only when they really exist.

**Surfaces:** inside the window, panels, controls (fields, selects, secondary buttons, switch tracks) and highlights are ink tints over what is behind them, never solid greys:

- **Controls:** `--surface` and `--surface-muted`.
- **Window glass:** `--background-1/2/3` turn into tints inside `.app-material`.
- **Bubble and highlights:** `--chat-bubble`, `--navigation-*`. The person's message bubble is compact (`.user-bubble`: 14 px corners, 8×12 px padding, at most 80% wide) and wraps greedily (`text-wrap: wrap`): WebKit's `pretty` wrapping shortened its lines and left an empty strip beside the text.

Portaled popups and dialogs keep their own material. With window glass on, every popup (menus, selects, tooltips, hover cards, the usage panel, dialogs) is glass: in dark, a 5% ink film over a blur of at least 24px, so it always reads a step lighter than what lies beneath; in light, `--floating-material` at `--popup-opacity` (0.4 × window opacity, clamped 24–80%). Controls inside are tints. The dialog overlay becomes a light shade without blur. The light palette has its own darker status colours.

Respect `prefers-reduced-motion`, keyboard use, `focus-visible`. Pointer glow stays **on the control**, never `pointermove` on `window`.

Drag reordering (sidebar project folders, header tabs, dock tabs, rail Customize) uses `src/lib/use-pointer-reorder.ts`: the row captures the pointer once it moves past a small threshold, with no window listeners and no HTML5 drag and drop, which the macOS webview does not deliver reliably. The dragged item lifts with a shadow (`[data-reorder-lifted]`) and follows the pointer within its list while neighbours slide aside to open its slot; transforms are written on the items and cleared on release. Each list keeps a keyboard alternative (Option+↑/↓ or arrows). The window sets `dragDropEnabled: false`, so the webview owns drag events; `main.tsx` only stops Finder files dropped outside a drop target from navigating the webview.

The composer's decorative 2 px chrome rim shares the Add button's liquid-metal shader with a bounded 131,072-pixel render budget. It pauses and dims while its textarea is focused, resumes in place on blur, and stops when offscreen, document-hidden, while the window lacks focus or while Settings covers it. The landing orbits and the waiting-approval orbit share the same window-focus/Settings gate (`src/lib/ambient-motion.ts`). While an agent works, the working model's mark runs along the composer's top edge (`ComposerRunner`, `src/lib/composer-runner.ts`, ADR-138) under the same gate, climbing onto the background tasks pill as a platform when it rests there; Appearance's typed `composerLineSpeed` (`slow` by default, `smooth`, `fast`) sets its pace and reduced motion parks it. This setting changes decoration only, never provider execution speed or permissions.

Switching provider in the composer's model picker plays an orbit swap on the trigger icon and, in the active pane only, a 5 s canvas scene behind the conversation in which the new provider's logo assembles from blocks (`src/lib/provider-scenes.ts`; ADR-068). The scene follows reduced motion and the ambient gate, and its canvas exists only while it plays. A transcript divider marks each reply answered by a different provider than the previous one, derived from native `TurnActivity.provider`; after Send, the pending handoff card flies into that divider. No IPC or persistence.

Native dictation uses a matching metal mic at rest and a silver orbital recording strip (orb, "Listening to you", waveform, timer) with two buttons while listening: ✕ Cancel and a round ✓ Finish. The model/approval/send controls yield to that strip, the rim rests and Send is blocked. Cancel discards the recording; Finish transcribes on-device and inserts the result once for review (Enter sends only with `dictationEnterSends`). On the phone the same component draws a bar, ✕ | waveform | time | ✓ (ADR-129). There is no live transcription, so the strip's caption stays static while recording. The orbital indicator and illustrative waveform follow animation preferences and pause offscreen/document-hidden; they do not measure audio levels. Changing composer draft owners stops dictation.

## Performance

The app may stay open for hours. No polling loops (exceptions: CI auto-fix polls PR checks every 60 s for at most 8 recent sessions, only while its setting is on, ADR-064; PR watch reads at most 8 watched PRs once a minute each, never for busy sessions, ADR-079). No global pointer listeners. Lazy `list_dir` — never walk `node_modules`; a shown tree follows the disk through a native watcher (ADR-109). Agent streaming is events, not timers; the renderer applies `agent-output` deltas once per animation frame. Stream persistence checkpoints are event-driven and coalesced (`persist::checkpoint_soon`: at most one write per second across streams, written outside the state lock; generation-ordered so an older snapshot never replaces a newer save). State lives in SQLite (`state.db`, ADR-114); a save writes only the rows that changed (a new message is one row), and the native process keeps only active, unsaved and the 6 most recently used transcripts in memory (ADR-047, ADR-099). The transcript mounts only its last turns (`src/lib/turn-window.ts`: 3 on first paint, 20 after a transition, 20 more per "Show earlier messages" or scroll near the top, wider before any jump), and a row re-renders only when its message or a session field it reads changes (`src/lib/transcript-row.ts`). Diffs mount in 400-row chunks (`src/lib/diff-window.ts`; one IntersectionObserver per diff list, 800 px ahead, unmounted rows keep their height), and only short untracked files are syntax-highlighted. Diff rows are memoized with stable props and the review comment draft lives in its own form, so typing in it re-renders no row. ⌘F (the find-in-conversation binding) opens a find bar in the diff while focus is inside it or the pointer is over it with no text field focused; matches cover every line (`src/lib/diff-find.ts`, at most 2000), ↑/↓/Enter step through them and the current match mounts the chunks up to it (ADR-102). Inactive terminal tabs stay mounted but use `visibility: hidden` + `content-visibility: hidden`, terminals read only their own settings fields, and scrollback is bounded to 1000–10000 lines on both sides. Views that do not read messages use `selectSessionsMeta` / `selectCurrentSessionMeta`; views that need another session's transcript use `useRetainedTranscripts`. Saving settings keeps unchanged fields by reference (`shareSettings`), and the transcript and composer select single settings fields, so layout toggles that save settings (sidebar, Environment) re-render neither (ADR-126). Running-status pulses and text shimmers step at about 15 fps and rest with ambient motion off. Blocking Git/filesystem/worktree commands run on native workers. Agent CLIs run at nice +5 (terminals do not), and all `gh` reads share one gate (ADR-100). After a clean turn, Codex, Claude, OpenCode, Devin, Hermes and Cursor keep their process for the session's next turn (`agent_pool.rs`: 30 idle minutes; how many is Providers → Advanced, All by default; ADR-107, ADR-108). Measurements and findings: [`docs/PERFORMANCE.md`](../PERFORMANCE.md).

## Process

### Features

1. This file + relevant ADRs + Graphify if structural.
2. Skills (few).
3. Short plan: modules, IPC, security.
4. Implement on the correct side of the boundary.
5. `npm run typecheck` and `cargo check` (and `npm run build` if frontend-visible).
6. `graphify update .` if structure changed.

Checks include `npm test` (Node built-in runner), `npm run lint` (ESLint bug rules and React hooks), and Rust unit/regression tests. Node 22.18+ is required for the test loader. Tests use disposable fixtures, never user repositories. Run `cargo fmt --check`, `cargo clippy --all-targets -- -D warnings`, and `cargo test` for native changes.

### Bugs

Reproduce, find the flow, Graphify if cross-module, fix the cause, check regressions. No cosmetic hacks over broken Git/agent state. The UI must show real install/git/process status.

### Dependencies

Refuse a new library if the tree already solves it. Weigh Tauri/macOS/size/security. Zustand stays the only client store unless an ADR says otherwise.

The Working panel beside the composer lists sessions in flight once two or more run (ADR-094; the switch is `showWorkingPanel`). ⌘Q needs a second press within two seconds unless agents are running, when the running-agents dialog asks (ADR-090). The four workspace commands run only in a selected-session view with Settings, palette and new-session dialogs closed. Native defaults must stay aligned with src/lib/keybindings.ts; regression checks enforce this contract.
