# Architecture reference

A detailed map of how Sirus Code is built today: modules, domain, IPC, providers, Git, security choices, design system and performance. It describes the code as it is, to save rediscovering it; it is a reference, not a rulebook. When the code and this page disagree, the code wins, and this page should be updated.

Contributor basics live in [`AGENTS.md`](../../AGENTS.md). Decision history lives in [`docs/decisions/`](../decisions/README.md).

## Stack (actual)

| Layer | Choice |
| --- | --- |
| Desktop | Tauri 2 (`com.siruscode.app`) |
| UI | React 19, TypeScript strict, Vite 8 |
| Style | Tailwind CSS v4 (`@tailwindcss/vite`) |
| Primitives | Radix + vendored UI Arc MIT components through existing primitives |
| Motion | `motion` (Motion for React) + CSS tokens |
| Diagrams | `mermaid` (lazy, strict, ADR-058) for fenced `mermaid` blocks |
| Icons | Phosphor (`@phosphor-icons/react`) through `src/components/icons/phosphor.tsx`; filled weight marks active items |
| State | Zustand (`src/store/app-store.ts`) — do not add another store |
| Native | Rust 2021 edition, crate `sirus-code` / lib `sirus_code_lib` |
| Git | Git CLI argv + worktrees |
| Terminal | portable-pty + `@xterm/xterm` |
| Persistence | JSON files (metadata index + per-session transcripts), not SQLite |

No Next.js. No Electron. No app login.

## Architecture (current)

```
React UI (src/)
  → SirusClient (src/client/index.ts)
    → Transport (src/client/transport.ts)
      → LocalTransport (src/client/local-transport.ts)  # Tauri invoke/listen
      → RemoteTransport (src/client/remote-transport.ts) # another device: WebSocket to remote.rs (ADR-080)
        → Tauri IPC
          → Rust commands (src-tauri/src/commands.rs + lib.rs pick_folder)
```

**UI must not import `@tauri-apps/api` except inside `LocalTransport`.** The UI served to another device uses `RemoteTransport` (ADR-080) for the same Client API; `isRemoteUi` tells the two apart.

Trust boundary: the webview is untrusted. Rust validates every path and every process spawn.

## Domain (as implemented)

- **Project** — user-added folder. `remove_project` drops metadata and sessions, **not** files on disk. Optional `look` (colour, emoji, logo or Astro icon; ADR-059) changes only its sidebar icon. Optional `scripts` (`setup`, `onFinish`; ADR-078) run in its sessions' isolated worktrees.
- **Session** — `idle | starting | running | waiting | completed | failed | stopped`. Owns `agent` (provider), optional `model` (CLI model id), `worktree`, `messages`, `lastError`, and last-admitted `execution` preferences (effort/Fast/planning/approval). Codex, Claude and OpenCode persist an exact `nativeThread` bound to session/project/canonical cwd/model; `pendingRequests` are live-generation-only and are never restored from disk. A coordinator may own a `team` (plan, tasks, merge state) and its helper sessions carry `teamWorker`. A side chat carries `sideChat.parentSessionId`. `scripts` holds `setupPending` (a new isolated worktree owes its Setup run) and the latest project script run of each kind (ADR-078).

**Team** (ADR-043) is a one-shot `+` → Equipe composer mode. The coordinator runs a read-only planning turn and returns at most 3 validated tasks, each with an assignee, planned paths and an optional earlier dependency. Nothing runs before the person confirms; edits are limited to titles, assignees and removing tasks. Each task becomes a normal session in its own isolated worktree. The worktree starts from a private snapshot commit of the coordinator checkout as it is now (uncommitted and untracked non-ignored files included; the person's index and files untouched), and each task runs using the person's Ask/Auto policy (never Full). Approvals stay with the person. A dependent starts only after its prerequisite succeeds. "Merge all" is explicit:

- it applies each finished task to the coordinator working copy in plan order, with no commits;
- before applying, it checks planned paths, then runs `git apply --check` against the current files;
- it stops at the first conflict without applying that task, offering skip, merge anyway (only for out-of-area changes) or Resolve with AI (only for conflicts). Resolve three-way-merges the current checkout snapshot into the helper's own worktree; leftover conflicts go back to that helper for one turn. Patches that still contain conflict markers are refused.

Cleanup of helper worktrees is confirmed; it first commits each helper's remaining edits to its own branch so worktrees are removed without force and nothing is lost. Helpers nest under the coordinator in the sidebar.
- **GitWorktree inventory** — real porcelain `-z` entries with path, HEAD, branch, detached/bare state, lock and prunable reasons.
- **Worktree** — `{ path, branch, isolated }`. Isolated trees live under app-data `worktrees/{projectId}/` with branch `sirus/<slug>-<id>`. Non-isolated uses the project checkout.
- **AgentProviderId** — `codex` | `claude` | `opencode` | `cursor` | `grok` | `antigravity` | `droid` | `pi` | `devin`. Session is an **agent** process; Settings lists **Providers** (the CLIs). Do not name the Settings section “Agents”.
- **Message** — user | agent | system; `streaming` flag. New native assistant responses optionally retain `activity` with per-turn provider/model, native timing and at most 128 observed tools/children. Rows keep a bounded `detail` and the reply `offset` where they began; the transcript interleaves text and work in that order, groups back-to-back rows into one sentence, shows the running step live and folds a finished turn behind "Worked for …" ([ADR-070](../decisions/ADR-070-t3-turn-timeline.md)); subagents show as cards with a state pill that open into their own steps. Children keep their native time window and up to 20 newest generic steps (400 per turn); no tool output, reasoning or child control. See [ADR-035](../decisions/ADR-035-native-turn-activity.md).
- **GitStatus / FileChange** — real `git status` / `diff`; never invent clean/dirty.
- **AppSettings** — `defaultAgent`, `defaultModel` (`provider::id`), `modelExecution` (qualified preferences), `openLastProject`, `disabledProviders`, `favoriteModels` (retained `disabledModels` is ignored: every model of an enabled provider is offered), `sidebarCollapsed`, `sidebarProjectOrder`, `sidebarProjectSortOrder`, `sidebarThreadSortOrder`, `pinnedProjectIds`, `pinnedSessionIds`, `archivedSessionIds`, `environmentPanelDefaultOpen`, `showEnvironmentUsage`, `showEnvironmentRepository`, `showEnvironmentEditor`, `showEnvironmentPullRequest`, `showEnvironmentPinned`, `showEnvironmentNotepad`, `showEnvironmentInstructions`, `enableProviderUpdateChecks`, `locale`, `customShortcuts`, `uiFontSize`, `confirmCloseRunning`, `restorePreviousSessions`, `developerLogs`, `computerUseEnabled`, `sidebarUsageProviders` (at most two providers that report usage, validated natively), `windowSnapEnabled` / `windowSnapShortcut` (closed presets, ADR-054), `steerWhileRunning` (ADR-062), `ciAutoFix` (ADR-064), Chat behavior (`dictationEnterSends`, `foldFinishedTurns`, `githubLinksInApp`, `diffWordWrap`, `confirmArchive`, `confirmTerminalClose`, `autoOpenSimulator`), `githubPins` (≤200 `owner/repo#n`), `railItemOrder` / `hiddenRailItems` (closed rail IDs, Home never hidden) / `railProjectShortcuts` (≤12), optional `worktreeBasePath`, `releaseWorktreeOnArchive` (ADR-078, off by default), `chatBackground`, `chatBackgroundEffect`, `chatBackgroundShowOn`, `chatBackgroundEmptyVisibility` / `chatBackgroundSessionVisibility` (ADR-089). A retained `profile`, `prWatch` from the removed Profile page is ignored, and so are `sidebarActivityView` and `doneSessions` from the removed Activity view (dropped on the next save).

Unsent composer drafts are owner-validated `project:<id>` / `session:<id>` keys in native `AppData`. Edits checkpoint at most every 250 ms, driven by incoming edits; shutdown saves the latest admitted edit. Metadata removal prunes its drafts. Restored content is never sent automatically. Unsent attachment metadata/goal edits/planning/debugging and provider-specific approval selections are memory-only owner-scoped context in the existing store; native selection/paste supplies bounded private file copies (8 files, 10 MiB each, 40 MiB per turn) or shallow folder names. Native clipboard path/image reads require a fresh once-only native Command-V admission matching the pasteboard change count; renderer byte uploads do not resolve paths. An admitted image can be annotated in the viewer; confirming uploads a bounded annotated PNG through that same byte admission, swaps the draft chip in place and releases the unsent original. Sent reference text becomes part of the persisted user message; binary payloads and preview URLs do not. Cache paths, binary fork reconstruction and attachment restoration after restart are unavailable. File-format interpretation still depends on the CLI/model and existing approval policy. See [ADR-012](../decisions/ADR-012-composer-execution-and-attachments.md) and [ADR-018](../decisions/ADR-018-native-file-and-clipboard-attachments.md).

Environment reference text lives in native `AppData.contextTexts`: `session:<id>` Notepad and `project:<id>` instructions. Values are bounded to 16,384 UTF-16 units / 64 KiB, owner-validated, pruned on metadata removal, and never sent to providers automatically. Edit-driven checkpoints share the draft gate; blur/unmount/retry flush and shutdown persists latest admitted values. The Environment card no longer mounts Pinned messages, Project instructions or Notepad, and General omits their visibility controls. Retained context text, message pins and legacy visibility flags remain compatible and are not deleted. See [ADR-030](../decisions/ADR-030-environment-context-references.md).

To add a provider:

2. `detect.rs` binary name.
3. argv in `agent.rs`.
4. `src/lib/provider-registry.ts` metadata/capabilities and provider asset.

Do not store vendor tokens. Use the CLI’s own login. Owner-authorized named Codex/Claude accounts may start fixed vendor login in a new private profile; never replace the default or a profile already used by sessions, copy tokens or accept auth material through IPC. Login output is discarded, bounded and secret-free; cancel/shutdown kills owned groups. Cursor/OpenCode named login is unavailable. No account removal or logout command. See ADR-015.

The UI shows the "In the background" strip on the composer (`BackgroundTasks.tsx`), state rows and a header pill with Resume (`src/lib/background-tasks.ts`). OpenCode retries every provider stream error indefinitely, and ACP does not report this. Native code reads only the main agent's error-level `stream error` lines; definitive ones (usage limit, quota, credit, billing, authentication) cancel the turn with the provider's bounded reason. ## Worktrees and Git

- Isolated worktrees: [ADR-004](../decisions/ADR-004-git-argv-no-destructive-defaults.md).
- **Never** automatically: `reset --hard`, `clean -fd`, `worktree remove --force`, force-push.
- Delete isolated worktree only with `confirm: true`; removal then prunes worktree metadata and the emptied project folder. Settings → Worktrees cleans up confirmed leftover folders no session references, keeping anything dirty or unverifiable; branches are never deleted (ADR-078).
- **Project scripts** (ADR-078): owner-saved Setup runs in a new isolated worktree after the first turn is admitted and before the provider starts; On finish runs after each completed or failed turn. Both run as the person in the worktree, bounded, and never fail the turn; the latest run shows above the composer.

The one exception is owner-enabled CI auto-fix (ADR-064): after its own fix turn it stages only that turn's files, commits and pushes the session branch (never forced; refused when unrelated changes are staged).

## Security

Treat project contents as untrusted.

- Canonicalize paths. Isolated session cwd is the worktree dir; non-isolated must stay under the project root (`session_cwd` in `commands.rs`).
- No path traversal, no shell strings for Git/agents. Native Git disables filesystem hooks/fsmonitor, refuses configured `hook.*` entries (Git 2.54 ignores hooksPath for those), and refuses affected operations when external checkout filters are configured. Inspectors and operations remove the config-only `GIT_CONFIG` override consistently; hook/filter inspection is names-only, output-bounded and deadline-bounded. These are preflight guards with a concurrent external-config-change limitation, not an OS sandbox. Never silently replace LFS/filter semantics. Automatic fetch remains unavailable until networking and ref import are config-isolated.
- PTY binary is not chosen by the UI ([ADR-007](../decisions/ADR-007-pty-is-user-shell-only.md)).
- Branch switch/create are explicit actions (`confirm: true`), validated against real local branches (charset + `check-ref-format`), and reuse the same hooks/filters guards as every other native Git command.
- Sidebar project rows show the checkout's uncommitted `+N -M` (`project_diff_stats` → `git::diff_totals`): tracked changes against HEAD plus the lines of up to 500 new text files (≤ 1 MiB each, binaries and links count as nothing). It is refreshed after a turn settles, after Git status refreshes (selection, commit, push) and on window focus, never on a timer.
- Push refuses project-local network helpers (`credential.*`, `core.sshCommand`, `core.gitProxy`, `core.askPass`, `remote.*.uploadpack/receivepack/proxy`, `url.*.insteadOf`, `http*.proxy`) because they can redirect credentials or connections.
- Editor files: read/overwrite only existing regular files inside the session cwd; `.git` paths are refused; 2 MiB read / 1 MiB write; opens use `O_NOFOLLOW` and re-verify the opened descriptor, and content is truncated only after verification.
- External links: http(s) only, no credentials in the URL, fixed host allowlist (`localhost`, `127.0.0.1`, `::1`, `github.com`). The GitHub URL is derived in Rust from `origin`, never rendered by the renderer.
- Provider updates: `provider_updates` reads only `registry.npmjs.org/<fixed first-party package>/latest` (no redirects/retries, bounded body, six-hour memory cache, no polling); `update_providers` requires `confirm: true`, validates ids against the native package map and runs a fixed `npm install -g` argv with bounded output/timeout. No renderer-supplied package, version, URL or flag.
- Provider conversation import was removed (ADR-021 superseded). Previously imported sessions keep `importOrigin` only for compatibility.
- CSP in `tauri.conf.json`. Do not load privileged remote content.
- Dictation is native macOS only (ADR-027): one process-wide session, fixed locale pair, bounded 300 s capture into a private temp `.caf`, transcribed once on stop with `DictationTranscriber` (punctuation, short-form) and deleted; `stop_dictation` returns the transcript and there are no `dictation` events; `Info.plist` carries the microphone/speech usage strings; the app binary needs the `/usr/lib/swift` rpath for the Swift bridge. No WebView speech APIs.
- Git runs from a fixed real binary (`/opt/homebrew/bin/git`, `/usr/local/bin/git`) before the `/usr/bin/git` shim, whose cold `xcrun` lookup can exceed the 4 s config-inspection bound (`git::git_binary`).
- Do not log tokens. Do not auto-run commands suggested by agent output.
- Remote access (ADR-080) is off by default and answers only loopback and Tailscale peers; a device token grants what the window can do, so `remote_*`, pickers, dictation, computer use and `plugin:` commands are refused over the socket and only token hashes are stored.
- Credentials are masked (`redact.rs` / `src/lib/redact.ts`, ADR-077): activity detail and command output before storage, approval-card commands, reasons, diffs and tool input at display. Secrets requested by agents never touch disk except the file the person approved or a turn-scoped private env file.
- Changes to IPC, FS, PTY, process spawn, or credentials need a security pass before “done”.

## Design system

Quiet at rest. Responsive in motion.

Reuse primitives before adding CSS. Arc integration and provenance: [`docs/development/ui-arc.md`](../development/ui-arc.md). The HTML declares CSS layer order before shared/lazy chunks. Tokens in `src/styles/index.css` (`--background-0`…`--accent`, `--motion-*`). No random hex, no random durations. Product typography uses the shared `ui-*` role utilities (titles, sections, controls, descriptions, captions, body/chat) in `src/styles/index.css`; role sizes follow `--ui-font-scale`. Do not choose independent font sizes in product components. See the [typography role table](../development/ui-arc.md#product-typography).

Launch has no splash (ADR-098): the main window is created hidden, Rust applies its appearance (glass or opaque) and shows it when the front end calls `window_ready` on its first ready paint (`src/lib/window-opening.ts`), or after a 2.5 s native fallback. The content is then wiped in from the left edge (`clip-path`, 550 ms) while the rail, header and main area slide in from the left (`src/styles/opening.css`, `html[data-opening]`); reduced motion gets a 150 ms fade. Settings is revealed by a circle from the rail's Settings gear and folds back into it; menu content enters from the direction of travel and the selection highlight glides between items.

**Popup rules** (every new popup follows them):

- **No instant mount or unmount.** Nothing floating may appear or vanish instantly; keep it mounted through its exit, with `AnimatePresence`, Radix `data-state="closed"` keyframes, or a delayed clear such as `afterToastExit`.
- **Dialogs:** rise 10px and grow from 95% on a light spring (about 0.28 s), with the overlay fading in alongside. They leave in about 0.15 s.
- **Menus, dropdowns, popovers and hover cards:** grow from 96% from their anchor or pointer in about 0.14–0.16 s, and leave in about 0.08–0.11 s.
- **One entrance (ADR-096):** popup boxes carry `data-popup` and enter on the shared `popup-in` keyframe (opacity and `scale` 0.96→1, `--motion-popup` 160 ms, `--ease-out`, from the Radix transform origin). They leave on `popup-out`, a `--motion-popup-exit` 100 ms fade. Use keyframes on `[data-state]`, not `@starting-style` transitions: Radix holds keyframes until the panel is positioned, while a transition runs off-screen and is mostly spent before the first paint in WebKit. Rows then cascade like the sidebar did (`cascade-in`: fade and `translate: -10px 0`, `--motion-slow`, 22 ms steps after the 40 ms `--cascade-lead`, capped at ten steps). Inside `[data-cascade]`, mark rows `data-cascade-item` with `cascadeIndex(i)`, or use `data-cascade="children"` to stagger direct children by position. Menus always cascade. Popovers opt in through `useCascade(open)` (`src/lib/cascade.ts`), which keeps the attribute for 640 ms after opening, so rows mounted later (search results, late data) just appear. Exits never cascade. Animations off, Reduce motion and `prefers-reduced-motion` turn the cascade off; the system setting leaves a plain fade on the box.
- **Toasts:** they stack top-center and all share the same entrance and exit.
- **Menu style:** a real icon in every action item, never the "···" placeholder. Groups are separated by a rule (ContextMenu `group`), and destructive items sit last in red. Shortcuts are shown only when they really exist.

**Surfaces:** inside the window, panels, controls (fields, selects, secondary buttons, switch tracks) and highlights are ink tints over what is behind them, never solid greys:

- **Controls:** `--surface` and `--surface-muted`.
- **Window glass:** `--background-1/2/3` turn into tints inside `.app-material`.
- **Bubble and highlights:** `--chat-bubble`, `--navigation-*`.

Portaled popups and dialogs keep their own material. With window glass on, every popup (menus, selects, tooltips, hover cards, the usage panel, dialogs) is glass: in dark, a 5% ink film over a blur of at least 24px (as in MonoCode), so it always reads a step lighter than what lies beneath; in light, `--floating-material` at `--popup-opacity` (0.4 × window opacity, clamped 24–80%). Controls inside are tints. The dialog overlay becomes a light shade without blur. The light palette has its own darker status colours.

Respect `prefers-reduced-motion`, keyboard use, `focus-visible`. Pointer glow stays **on the control**, never `pointermove` on `window`.

Drag reordering (sidebar project folders, header tabs, dock tabs, rail Customize) uses `src/lib/use-pointer-reorder.ts`: the row captures the pointer once it moves past a small threshold, with no window listeners and no HTML5 drag and drop, which the macOS webview does not deliver reliably. The dragged item lifts with a shadow (`[data-reorder-lifted]`) and follows the pointer within its list while neighbours slide aside to open its slot; transforms are written on the items and cleared on release. Each list keeps a keyboard alternative (Option+↑/↓ or arrows). The window sets `dragDropEnabled: false`, so the webview owns drag events; `main.tsx` only stops Finder files dropped outside a drop target from navigating the webview.

The composer's decorative 2 px chrome rim shares the Add button's liquid-metal shader with a bounded 131,072-pixel render budget. It pauses and dims while its textarea is focused, resumes in place on blur, and stops when offscreen, document-hidden, while the window lacks focus or while Settings covers it. The landing orbits and the waiting-approval orbit share the same window-focus/Settings gate (`src/lib/ambient-motion.ts`). Appearance persists its typed `composerLineSpeed` (`slow` by default, `smooth`, `fast`); it follows the existing animations/reduced-motion preferences. This setting changes decoration only, never provider execution speed or permissions.

Switching provider in the composer's model picker plays an orbit swap on the trigger icon and, in the active pane only, a 5 s canvas scene behind the conversation in which the new provider's logo assembles from blocks (`src/lib/provider-scenes.ts`; ADR-068). The scene follows reduced motion and the ambient gate, and its canvas exists only while it plays. A transcript divider marks each reply answered by a different provider than the previous one, derived from native `TurnActivity.provider`; after Send, the pending handoff card flies into that divider. No IPC or persistence.

Native dictation uses a matching metal mic at rest and a silver orbital recording strip with Cancel/Finish while listening. The model/approval/send controls yield to that strip, the rim rests and Send is blocked. Cancel discards the recording; Finish transcribes on-device and appends the result once. There is no live transcription, so the strip's caption stays static while recording. The orbital indicator and illustrative waveform follow animation preferences and pause offscreen/document-hidden; they do not measure audio levels. Changing composer draft owners stops dictation.

## Performance

The app may stay open for hours. No polling loops (exceptions: CI auto-fix polls PR checks every 60 s for at most 8 recent sessions, only while its setting is on, ADR-064; PR watch reads at most 8 watched PRs once a minute each, never for busy sessions, ADR-079). No global pointer listeners. Lazy `list_dir` — never walk `node_modules`. Agent streaming is events, not timers; the renderer applies `agent-output` deltas once per animation frame. Stream persistence checkpoints are event-driven and coalesced (`persist::checkpoint_soon`: at most one write per second across streams, written outside the state lock; generation-ordered so an older snapshot never replaces a newer save). `state.json` is compact JSON without transcripts; only loaded, changed `sessions/<id>.json` files are rewritten, and the native process keeps only active, unsaved and the 6 most recently used transcripts in memory (ADR-047, ADR-099). The transcript mounts only its last turns (`src/lib/turn-window.ts`: 3 on first paint, 20 after a transition, 20 more per "Show earlier messages" or scroll near the top, wider before any jump), and a row re-renders only when its message or a session field it reads changes (`src/lib/transcript-row.ts`). Views that do not read messages use `selectSessionsMeta` / `selectCurrentSessionMeta`; views that need another session's transcript use `useRetainedTranscripts`. Blocking Git/filesystem/worktree commands run on native workers. Measurements and findings: [`docs/PERFORMANCE.md`](../PERFORMANCE.md).

### Bugs

Reproduce, find the flow, Graphify if cross-module, fix the cause, check regressions. No cosmetic hacks over broken Git/agent state. The UI must show real install/git/process status.

### Dependencies

Refuse a new library if the tree already solves it. Weigh Tauri/macOS/size/security. Zustand stays the only client store unless an ADR says otherwise.

Persistence: `~/Library/Application Support/com.siruscode.app/state.json` (metadata), `sessions/<id>.json` (transcripts) and `thumbnails/<id>.jpg` (sent image thumbnails) on macOS. See [ADR-047](../decisions/ADR-047-per-session-transcript-files.md).

Settings persistence runs on native workers. macOS uses a custom native Quit menu item so Command+Q enters the native exit guard rather than predefined NSApp termination. Closing/Quit with native agent handles or Starting admission can require one native confirmation; decline preserves execution. Session reopening controls automatic selection only, preserving all saved sessions/drafts and never starting processes. Developer diagnostics contains fixed aggregate lifecycle counts only, rotating two private 256 KiB files under app data.

Shortcuts (centralized, defaults; custom overrides validated against reserved keys/collisions): ⌘K palette, ⌘N new session, ⌘T new blank tab of the selected project (fixed), ⌘B sidebar, ⌘, settings, ⌘\ right panel, ⌘` terminal, ⌘[ back, ⌘] forward, ⌘. stop (Escape also stops the selected running agent when focus is in the composer/transcript or nowhere, and no Settings, palette, dialog, menu or Environment card claims it), ⌥⌘O Files, ⌥⌘B Browser, ⌥⌘E Environment, ⌥⌘S side chat, ⇧⇥ cycle reasoning effort in the composer (the only Tab binding; ADR-089).
