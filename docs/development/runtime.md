# Runtime guide

The [working contract](../../AGENTS.md) defines the trust boundary and command surface. This guide explains how the implemented domains fit together.

## Providers and models

A provider is a host CLI adapter, not a session or a model. Frontend metadata and capabilities live in `src/lib/provider-registry.ts`; executable lookup, argv and output decoding live in `detect.rs`, `agent.rs` and `agent_output.rs`. `cli_output.rs` captures read-only version/catalog commands with time and output bounds, keeping the child unreaped until its pipes drain so timeout cleanup still owns the original Unix process group. No vendor credentials are stored by Sirus Code.

Catalogs are cached in the existing Zustand store and loaded on demand. Opening Settings does not trigger provider detection. Explicit refresh runs bounded probes concurrently: version probes have a three-second timeout, catalog commands twelve seconds. A configured executable that is invalid is reported unavailable instead of silently falling back to PATH.

| Provider | Model strategy | Verification |
| --- | --- | --- |
| Codex | `codex debug models`, JSON `models[].slug` | Local command returned a real catalog |
| Cursor | `cursor-agent --list-models`, CLI rows | Local command returned a real catalog |
| OpenCode | `opencode models`, provider/model IDs | Local command returned a real catalog; this does not prove account access |
| Claude Code | CLI initialize `models` response, no inference | Verified locally in safe mode; legacy failure falls back to explicitly unknown [documented aliases](https://code.claude.com/docs/en/model-config) |
| Grok | `grok --no-auto-update models`, CLI rows | Official temporary 1.0.46 binary returned real rows and reported unauthenticated; those rows are unavailable until the vendor CLI is signed in |

`model-registry.ts` composes catalog rows with provider enablement, model enablement, brand and favorites. Model-specific capabilities remain explicitly unknown (`null`) because CLI catalogs do not prove vision/tool support; provider execution capabilities are a separate registry concern. Disabled/unknown descriptors remain available to Settings while selectable rows are filtered. Identity is **provider + model ID**; similar names across providers are preserved. Disablement applies to future selection; existing Sessions keep their saved provider/model and may continue running. Unknown documented aliases are visibly marked unknown in Settings and are excluded from new-session catalog selection. Claude supports its real CLI catalog and explicit CLI-default choice. Catalog presence still does not prove every model is runnable under the account. A CLI-default choice delegates model selection to that provider, without inventing a discovered model. `model-brand.ts` resolves family branding centrally, independently of the hosting provider. Assets and provenance are documented under `src/assets/*/SOURCES.md`.

## Sessions and workspaces

New Session selects project, model/provider and either the current checkout or an isolated Git worktree. Saved defaults shorten the flow. Sessions store the provider, optional model, project ID, worktree path/branch, timestamps, status and conversation. Process handles belong to native memory and are never serialized.

Codex, Claude Code and OpenCode have passed actual edit/stream/exit tests in disposable isolated worktrees, leaving the original checkout unchanged. Codex also passed with the discovered model `gpt-6.1-sol`. Cursor also passed an actual safe file edit using CLI 2026.09.28 with `--auto-review --sandbox enabled`. Its current installed help adds this classifier to the older force-only headless documentation. Default mode uses no force/yolo; explicit Full uses the process-only profile in ADR-017, without a persistent vendor permission change; manual calls requiring approval remain unsupported in the Cursor adapter. Grok 1.0.46 was retrieved from the official artifact endpoint into a disposable tool folder; help, model rows and upstream streaming reducer were verified, but it reports no authentication. No Grok inference or user login/config change occurred.

Codex starts an owned `codex app-server --stdio` process for each turn and resumes the exact saved native thread on follow-up. It checks the session/project/canonical workspace/model binding and never substitutes a latest thread or replays textual history. Default thread and turn requests use workspace-write/on-request with the user reviewer; default sandbox roots are restricted to the validated workspace, temporary-root exceptions and network access are disabled. Explicit Auto/Full profiles and restrictive restoration are defined in [ADR-017](../decisions/ADR-017-per-turn-approval-profiles.md). Ordinary command/file approvals and non-secret user questions appear in the Session pane. File approvals include native paths/diffs. Decisions apply to one registered request only; persistent grants, permission amendments, managed-network/stdin approvals, grantRoot expansions, secret questions and unsupported protocol methods are denied. Pending callbacks are bound to the live process generation/turn and consumed once; vendor resolution, turn completion, Stop and restart invalidate them. Native interruption gets a bounded cleanup window before owned process-group termination. CLI initialization/account fields are never transcript output. See [ADR-009](../decisions/ADR-009-native-codex-interaction.md).

Claude starts one owned bidirectional stream-json process per turn with typed per-turn permissions (manual by default). Reviewable built-in tools are shown with their original native input; an allow decision echoes that retained input without renderer edits or permission amendments. Native callback identity is consumed once; vendor cancellation, Stop, completion and restart invalidate pending requests. Follow-ups resume only the exact saved Claude session, bound to Session/project/canonical workspace/model, without textual replay. AskUserQuestion, secret input, MCP and unsupported tools are denied explicitly. Actual isolated Write approval, Write refusal and memory-only exact follow-up tests passed. See [ADR-010](../decisions/ADR-010-native-claude-interaction.md).

OpenCode uses one owned ACP process per turn. Native session identity is bound to Session/project/canonical workspace/model and exact `session/load` suppresses vendor history replay. Model selection requires an offered ACP model value. Only native reviewable file edits inside the workspace can receive a host allow-once or reject-once decision; other callbacks are denied. Default child configuration disables sharing, requests edit approvals and denies shell/network/external-directory tools globally and for the build agent. Auto/Full profiles change only the owned child configuration as described in ADR-017; unsupported host callbacks remain denied. ACP is not a filesystem sandbox; vendor plugins and managed configuration remain vendor authority. Live ACP validation is documented in [ADR-011](../decisions/ADR-011-native-opencode-acp.md).

Cursor and Grok retain single-shot CLI processes. Their follow-ups include up to eight prior non-streaming user/assistant messages, bounded to 32 KiB; a current prompt is limited to 64 KiB. This is explicit textual context, not vendor-native resume or a full interactive TUI. Structured interaction remains unavailable in those fallback adapters. Composer context is explicit: users can attach the displayed diff and workspace metadata as reference snapshots, bounded to 12 KiB. No additional filesystem reads or automatic attachment occurs. Drafts remain independent per Session/project and persist through the native JSON store. A scoped owner-validated IPC admits unsent text (64 KiB UTF-8 maximum), serialized/coalesced per draft in the renderer. Native checkpoints are edit-driven at most every 250 ms; shutdown saves the latest admitted state. Removing metadata prunes its drafts and rejects late saves. Restoring a draft never starts an agent. A sudden kill can lose edits since the last checkpoint.

Rust owns `starting → running ↔ waiting → completed | failed | stopped`, output accumulation and persistence. It publishes `session-updated` snapshots, normalized `agent-output` chunks and `agent-exit`. Output events carry native message IDs, first-message snapshots and UTF-16 offsets so replayed chunks cannot duplicate content. Stderr creates separate System diagnostics, collapsed in the transcript and excluded from follow-up context. Lines are bounded to 1 MiB and each visible message to 8 MiB. Native protocol failure remains failure even if the process exits zero. UI responses never overwrite newer streaming state. Stop interrupts process wait; Unix agents use a dedicated process group so cancellation includes descendant tools. Readers drain before completion. App shutdown stops owned processes and PTYs. Restart converts persisted active states to stopped, preserving saved messages and reporting interruption. Streaming saves event-driven checkpoints at roughly one-second intervals; completion/shutdown save the final state. A sudden crash can lose output since the last checkpoint. No polling timer or crash-proof journal is claimed. Recovery clears stale streaming flags even for inactive Sessions; a late process exit cannot replace an interruption reported at shutdown.

Named Codex/Claude accounts pin process and exact-resume profile identity independently of new-session defaults; quota and reset probes use the same profile. Their fixed browser login and external-reauthentication limitations are documented in the [usage and account guide](provider-usage.md).

Composer effort, Fast, planning and native capability discovery are documented in the [provider execution guide](provider-execution.md); the native catalog is authoritative. Approval profiles are documented in [ADR-017](../decisions/ADR-017-per-turn-approval-profiles.md). CLI System diagnostics remain available in the context panel; actual turn failures remain visible in the conversation.

## Worktrees and review

Isolated worktrees use unique branches and paths. Branch names are validated before creating a directory. Removing an isolated worktree requires confirmation and refuses tracked or untracked changes; no force flags are used. Session deletion removes metadata only after worktree removal succeeds. Removing a project from the list preserves disk files and refuses active agent execution.

Git status parses NUL-delimited records, preserving spaces, quotes, Unicode and newlines. Diff includes staged and unstaged changes and rejects traversal or symlink escapes. External Git diff drivers and text converters are disabled. Tracked base/index blobs and working/untracked text previews are bounded to 2 MiB. Directory and special-file previews are refused; regular files are opened without following the final symlink on Unix and descriptor paths are revalidated on macOS/Linux. Native Git disables filesystem hooks/fsmonitor, refuses all effective `hook.*` configuration (Git 2.54 configured hooks bypass hooksPath), and refuses automatic operations affected by configured external checkout filters, preserving LFS/filter semantics. Configuration inspection is a preflight check; concurrent external changes to config/includes can still race the subsequent Git process. This is not an OS sandbox. Automatic fetch stays unavailable because URL rewrites, scoped headers/helpers and object/ref import require a config-isolated design; users can fetch explicitly in their own terminal. Read-only Git/filesystem commands and worktree mutations run on native blocking workers rather than the UI event thread. Git refresh is explicit or follows agent exit/selection, not a polling loop. File trees load one directory at a time and ignore heavy build/dependency directories.

Files supports explicit empty-file/folder creation and Collapse all; creation ownership and platform limits are described in [ADR-044](../decisions/ADR-044-explicit-workspace-entry-creation.md). Live Changes provides prepare/unprepare, matching index/worktree diffs, editable local title suggestions, staged-only Commit, confirmed Push and bounded local ancestry; it remains separate from retained turn reviews. Index tokens, nested-project commit scope and external-Git race limits are described in [ADR-045](../decisions/ADR-045-explicit-git-index-workflow.md).

The terminal is a separate user-shell PTY rooted in the Session workspace. It supports input, resize, cleanup and reopen. Listener registration precedes spawn; per-session queues and native generation IDs prevent stale cleanup/output from affecting a reopened terminal. UTF-8 decoding preserves characters across reads. Leaving the terminal panel closes its shell; persistent detached terminals are not implemented. Unix cleanup signals processes still belonging to the owned PTY session, including ordinary background jobs in separate process groups. Deliberately detached sessions are outside ownership. PID/session checks have the usual POSIX check/use race; no pidfd-strength guarantee is claimed. Tests verify owned shell/background termination and survival of an unrelated process.

## Preferences and lifecycle

UI text sizes use proportional central font tokens independently of density and terminal font size. Custom shortcuts persist in settings, use the existing single central controller and effective hints, and reject collisions, unsupported combinations and reserved editing/system keys. The Arc recorder captures keys locally and cannot override validation. Settings search supports arrows/Enter and Escape within the full-page focus scope.

The close/Quit preference asks through a single native dialog while owned agent handles or Starting admission exist. Decline leaves work running; accepted normal exit invokes owned-process shutdown/persistence. Session reopening controls automatic selection only (latest saved Session in the most recent valid Project); it preserves all metadata/drafts and never auto-sends or starts agents.

Opt-in developer diagnostics writes only timestamp, project/session counts and provider/status totals under app-data logs. No prompts, output, paths, identities, arbitrary errors or credentials enter it. Unchanged snapshots are deduplicated; two files rotate at 256 KiB, symlinks are rejected, and Unix file creation is private. Logging failures produce a fixed native warning without changing successful state persistence. Automatic updater has no configured signed release endpoint; it remains explicitly unavailable, as do unspecified experiments.

## Transport and security

All frontend native access passes through `SirusClient` and `LocalTransport`. Only LocalTransport imports Tauri APIs. Renderer commands cannot append arbitrary assistant output or declare process completion. No RemoteTransport or arbitrary shell command IPC exists.

Production CSP permits bundled assets and local IPC; Vite/HMR and eval allowances exist only in development CSP. Opening a directory is restricted to registered projects, app data and configured worktree roots. Native Git/agent execution uses argv arrays. Git test fixtures execute only hard-coded commands against their own temporary directories.

## Verification limits

Live native integration passed with existing CLI authentication. Actual isolated desktop fixtures cover Session/worktree creation, Codex edits, Claude host Write approval and exact follow-up/restart continuation, sidebar/palette, Settings focus containment, language/favorite/draft restart persistence, terminal input/keyboard resize/close/reopen and Git/diff inspection. These targeted checks do not prove every model, permission, gesture or platform. All 100 Arc previews pass server rendering; native gallery interaction is separately recorded in the overnight evidence. Windows/Linux runtime is not validated. No credentials were changed. See the [build guide](building.md) and [overnight evidence](../OVERNIGHT_PROGRESS.md) for checks and limitations.

## Additional local CLI providers

Antigravity, Droid, Pi and Devin use constrained print adapters and bounded fallback history. Installation, fixed argv, catalog discovery and permission limits are specified in [ADR-026](../decisions/ADR-026-additional-local-cli-providers.md). Their version/help/catalog probes were checked locally; new-provider authenticated inference is not yet verified. Sign in through each vendor CLI outside Sirus Code; no app-generated login or copied credentials are used. Devin requires an already trusted workspace.
