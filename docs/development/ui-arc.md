# UI Arc integration

Switchyard vendors the public MIT component source from [UI Arc's registry](https://uiarc.dev/docs/installation), retrieved on 2026-10-01. `src/components/arc/catalog.json` records all 100 free entries and original upstream file hashes; `src/components/arc/LICENSE` retains attribution. Pro assets are not included.

Existing primitives adapt Arc rather than creating a second product API. The foundation maps Arc surfaces, controls, fonts and motion durations to Switchyard tokens. Keyboard focus stays visible; the upstream global focus suppression is deliberately excluded. All components honor both OS reduced motion and the host MotionConfig. Next-specific avatar/breadcrumb imports use native React images/anchors; no framework migration is involved.

The HTML declares `theme, base, components, utilities` before Vite loads any shared/lazy CSS chunk. Component styles sit in the `components` layer, so host utility classes can adjust dimensions without Tailwind resets erasing the component's padding or border. Keep this declaration when changing bundling.

Arc Textarea's host `plain` variant embeds the control in the composer surface; the composer supplies visible keyboard focus on its outer border. Other forms retain the default field border and focus ring. The shared model picker uses one trigger showing only the model-family icon and clean model name. A row of provider icon tabs on top, with a gliding highlight, switches provider-scoped catalogs (←/→ between tabs, ↓ into the list); only selecting a model commits its exact provider/ID. Favorites span available, enabled, installed providers and retain provider identity. The composer opens the approved Orbit effort panel first; its model-name button switches to the tabbed catalog in the same popover. Selection returns to effort controls. Other callers open the catalog directly. Search receives focus in the catalog; arrows navigate providers/models and Escape returns to the trigger. A saved null model stays null until explicit selection and displays “Select model”; there is no synthetic CLI-default row or automatic model assignment. Cursor effort/context presets are grouped for presentation only in `model-registry.ts`; Settings retains the exact catalog entries and preferences. A current session's offered ID takes priority, then a native parameterized base entry, then saved favorites, then the entry with the least suffix metadata. Names never become CLI arguments; the chosen catalog ID does. Effort/Fast controls use discovered capabilities and real adapters, with Fast on the lightning button. The bar keeps the current design; higher effort heats the model colour toward red, adds embers and speeds the motion, and Fast adds a lightning strike. The panel shows no tooltips. Small transform/opacity layers and SVG stroke motion stop when the panel unmounts, is offscreen, the document is hidden or motion is reduced. The plus panel contains picker-backed files/folders, goal and planning; permissions select the typed native profiles in [ADR-017](../decisions/ADR-017-per-turn-approval-profiles.md). Add and approval panels measure the full composer once on open and explicitly override the shared Arc width cap, aligning both input edges with viewport collision limits. The effort panel is 280 px wide, centered directly above the model trigger with a 6 px gap; the catalog uses 360 px and the same trigger anchor. Only Add/approval panels use the full composer as their upper boundary. Automatic effort keeps decorative energy and a working Fast control where offered, without pretending to provide an adjustable range. The image viewer draws pointer markup on a canvas and replaces the original chip only after the annotated PNG passes the same bounded native attachment admission ([ADR-018](../decisions/ADR-018-native-file-and-clipboard-attachments.md)). Limits and mapping live in [ADR-012](../decisions/ADR-012-composer-execution-and-attachments.md).

Live code output uses Arc CodeBlock with `animateChanges={false}`: copying, syntax highlighting and expansion work, while incoming chunks do not animate the entire source repeatedly. App strings use Switchyard i18n. Imported source examples and unused component defaults are not claims of implemented product features.

Advanced Settings opens a lazy component explorer with all 100 real components, searchable by name/category. Only the selected preview mounts. Examples are labeled local demonstrations and make no native/network/payment claims; `npm run test:arc` verifies exhaustive coverage and renders every entry. The gallery is intentionally outside initial startup/Settings chunks; its approximately 754 kB JavaScript chunk remains a build-size warning. Not every chart/form belongs in a coding workflow; the explorer satisfies access to the complete free kit without pretending demonstration data is product functionality.

Provider model menus and Settings order numeric generations descending within each model brand; unknown brands keep separate name families. Context capacity and date suffixes are not version numbers, and unversioned names do not acquire invented release dates. Favorites retain their own cross-provider rail instead of moving older generations above newer ones in provider menus. Sorting changes presentation only; saved model IDs and current preset selection remain intact.

Host-facing menus/dialogs use brief opacity/scale/4px transitions and trigger origins. Dialog supports an optional compact density for short destructive confirmations; the default layout remains unchanged. Session deletion uses the existing danger token for its filled confirmation button. Error Toasts have error semantics and stay until dismissed. File context menus copy the real path. Inline gallery menus stay within the outer Dialog's focus/pointer scope; nested Escape closes the menu first. BottomSheet uses local pointer capture rather than global pointer tracking. These interactions passed source review. Actual desktop checks also exercised nested dropdown keyboard selection, Escape ordering and focus return inside the Settings explorer; all 100 previews are render-tested rather than exhaustively gesture-tested.

UI Arc Pro is explicitly excluded by the owner; no paid license or source was acquired. Free-source provenance does not imply rights to paid components.

## Product typography

Product components use semantic `ui-*` utilities from `src/styles/index.css`, rather than choosing a font size independently. The same role includes font size and line height; titles additionally define their weight. Every role uses the existing `--ui-font-scale` preference.

| Role | Base size | Use |
| --- | --- | --- |
| `ui-title` | 18 px, medium | Page headings |
| `ui-dialog-title` | 15 px, medium | Dialog, effort and account/usage panel titles |
| `ui-section-title` | 13 px, medium | Settings groups, context panels and board columns |
| `ui-brand` | 14 px, semibold | Compact sidebar product name |
| `ui-control` | 12 px | Buttons, navigation, menu/model rows and field labels |
| `ui-description` | 11 px | Menu descriptions and secondary help; wraps naturally |
| `ui-caption` | 11 px | Menu group captions, timestamps and status metadata |
| `ui-micro` | 10 px | Compact keyboard hints and technical paths |
| `ui-body` | 13 px | Explanatory body text and larger inputs |
| `ui-chat` | 14 px | Conversation text and composer content |

Add and approval panels share 12 px item titles, 11 px descriptions/group captions, 15 px control icons and compact row spacing. Menu content must not fall back to a larger inherited body size. Arc foundation font aliases map forms, select menus, tooltips and dialogs onto this same host scale; imported demonstration content retains its own hierarchy. Terminal text still follows its separate terminal font preference, and code/diffs keep the monospace family.

## New thread orbit background

The empty landing mounts `LandingOrbits.tsx` behind its existing content; sending the first message removes the background. The shared Canvas 2D drawing in `src/lib/landing-orbits.ts` is the same geometry used by the approved Órbitas preview, fixed at 100% intensity and its Fast (1×) speed. The center remains clear, controls retain pointer/focus behavior, and a token-based shade protects the welcome text. Light mode uses the existing text color token.

`src/lib/landing-orbit-motion.ts` owns a 900,000-pixel render cap and approximately 30 fps, with size measured only by ResizeObserver. Local composer focus stops time and dims the background; blur resumes from the same frame. Hidden documents, offscreen surfaces and the existing OS/app motion preferences suspend the loop. Reduced motion retains a static frame. Unmount disconnects all resize, intersection and theme observers, removes owned focus/visibility listeners and cancels the frame request. No per-frame React state, polling, dependencies, settings fields or IPC are introduced.

## Composer metal surface

The full composer reuses the Add button's liquid-metal shader and shared material uniforms (`src/lib/composer-metal.ts`). The border uses cover sizing rather than the round button's contain sizing so the material reaches all sides and corners of wide or tall composers. A CSS mask confines the surface to a 2 px chrome rim; its center stays transparent and pointer events stay on the existing controls. The mount caps rendering at 131,072 physical pixels and handles resize, offscreen and document visibility suspension. Local focus events stop shader time while the textarea is focused, then resume in place; speed and reduced-motion changes reuse the same mount. Reduced motion keeps a static reflection, and unavailable WebGL retains a CSS metallic rim. Effects load lazily, with owned listener/context cleanup and no polling or per-frame React updates. Appearance reuses the existing segmented primitive as a rounded Slow/Smooth/Fast pill. `AppSettings.composerLineSpeed` is a closed native enum, persisted through the existing settings command and defaulting legacy state to Slow; it never changes provider execution options.

The Add trigger retains its existing Radix button and picker-backed menu. Its decorative chrome follows [johuniq’s Liquid Metal Button reference](https://www.jolyui.dev/docs/components/buttons/liquid-metal-button), using the actual liquid-metal shader from pinned `@paper-design/shaders` 0.0.81 (Apache-2.0, no runtime dependencies). Existing CSS/Motion primitives cannot reproduce that material’s fluid reflection field. Only the mount and this shader load in a separate chunk; no external content, image textures or native permissions are needed. The surface is confined to the 36 px control, with a bounded 72 × 72 pixel render budget.

Idle controls render a static frame; hover or keyboard focus animates the border, with a brief activation pulse. The mount pauses while offscreen or document-hidden, and is disposed on unmount or disabled/reduced-motion changes. Reduced motion and unavailable WebGL retain a static CSS metallic border. The original Plus icon, accessible name, keyboard focus and menu opening remain on the existing trigger. License and NOTICE files ship under `public/licenses/paper-shaders/`.

## Sidebar rows and hover cards

The app uses one icon family, **Phosphor** (MIT, `@phosphor-icons/react`). Call sites import from `src/components/icons/phosphor.tsx`, which keeps the Lucide-era names stable, maps each to the closest Phosphor glyph and turns `fill` (other than `none`) into the filled weight. Rail buttons are 36 px with 20 px glyphs; the active rail item (Home, Kanban, Archives, Pull requests, Automations) uses the filled weight over the solid `--background-3` surface. Bespoke glyphs remain only where no library icon fits: the drafts feather, the dictation mic, the handoff mark, terminal split marks and the window-capture mark.

The sidebar follows Synara’s compact rhythm: 28 px project/session rows at the default scale, 13 px regular labels through `ui-body`, 15 px Phosphor folder / folder-open glyphs and 12 px original model/provider SVGs. Leading folders yield to a pin on hover or keyboard focus; project actions remain separate buttons. Pinned sessions form a global section rather than duplicate rows. Archive and restore use the organization settings described in [ADR-029](../decisions/ADR-029-sidebar-organization.md).

`SidebarHoverCard` anchors the existing Radix-backed Popover without moving focus on pointer entry. The 256 px cards use compact 12 px metadata, subdued separators and a translucent token-based surface. Their -2 px side offset overlaps the row, while a bounded motion-token close delay keeps their controls reachable; Arrow Right reaches its actions from a focused row. Escape dismisses it, and CSS respects reduced motion. Existing Arc context menus retain Rename/Delete session and Remove project on right-click or Shift+F10. There are no global pointer trackers or polling loops.


Sidebar project titles support vertical drag ordering with an insertion line and Option + Up/Down keyboard moves. Manual order is owner-validated in `sidebarProjectOrder`; pinned projects stay first. Expansion uses an interruptible grid `0fr`/`1fr` transition and a small content fade/drift using the shared normal motion token. Collapsed rows are inert and hidden from accessibility. The sidebar coordinates hover cards so switching rows immediately removes the previous card; the short leave grace period only bridges pointer travel into the interactive card. No polling or global pointer listeners are added.

## General preferences and Orbit switches

The selected study 3, Orbit, now styles the shared production `Switch`: a 46 × 26 px track inside a 52 × 40 px button, a 20 px silver pearl, a short 120° orbital turn on activation and a satin-silver enabled track. Existing Radix owns checked/disabled semantics and keyboard handling. Motion uses host tokens and is finite; OS/app reduced motion and disabled animations remove transitions and rotation. Light mode adjusts the off track. Decorative geometry is hidden from accessibility; row labels or explicit names label controls. No tooltip, canvas or continuous loop is added.

General uses soft 12 px grouped cards and existing typography. It exposes the installed/enabled provider registry for future sessions, workspace and language defaults, project/session ordering, existing startup/close preferences and Environment section visibility. Changing the default provider retains a compatible model or clears a foreign model; it never changes the selected session. General has one Restore defaults button beside its page title, disabled when its preferences match the defaults. It resets only that page, preserving other pages, pins, manual project order and reference content; a foreign default model is cleared when the default provider changes. Persistence uses the existing serialized settings queue and closed native sort enums described in [ADR-029](../decisions/ADR-029-sidebar-organization.md). Environment visibility follows [ADR-019](../decisions/ADR-019-header-environment-dock-and-editors.md). Environment references reuse Arc Textarea with associated hidden labels, native disclosure controls and host focus/error styles; ownership and autosave follow [ADR-030](../decisions/ADR-030-environment-context-references.md). `node scripts/verify-general-settings.mjs` checks real server renders, escaped reference text, owner selection and accessible switch/textarea states without IPC or a browser.

Default provider, New threads, Language, Project order and Thread order use the same Arc/Radix `Select` through the typed `primitives/Select` adapter. Its host `hideLabel` option keeps an associated native label visually hidden when a settings row supplies the visible title. Controls and menus are 200 px wide; controls are at least 32 px tall and narrow layouts wrap the row. Arc retains value/menu motion, selected indicators, typeahead, keyboard navigation and focus restoration. Optional decorative option icons appear in both the selected value and menu; optional descriptions explain disabled provider availability without changing the selected label or typeahead text. The adapter refuses disabled values before calling the host save action.

The shared silver Orbit switch uses a 36×20 px track, 14 px thumb and 18 px orbit within a 42×32 px keyboard-focusable hit area. The finite transition and reduced-motion behavior remain. Environment PR details use the existing Popover and InteractiveButton, with explicit refresh and no hover tooltips; metadata follows [ADR-031](../decisions/ADR-031-read-only-pull-request-checks.md). `node scripts/verify-pull-request.mjs` checks real rendered states, escaped content, commit identity and visibility without IPC or a browser.


## Keybindings

Keybindings settings groups the centralized command reference by category and searches translated labels, descriptions, defaults and effective combinations. Arc ShortcutRecorder handles key capture/cancellation and physical key identity. Its host `showReset` extension hides individual reset buttons; one page-wide Restore defaults clears only customShortcuts. Conflicts name the occupied command. Per-action edits merge into the latest optimistic settings before the existing serialized save queue. Native validation and frontend registry remain aligned, including Forward and the three built-in session-only pane commands. No free-form command/condition evaluation is exposed. `scripts/verify-keybindings.mjs` checks real recorder renders in both locales; keyboard controller tests cover recording isolation and built-in workspace context.
