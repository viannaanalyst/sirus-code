# ADR-145: Virtualized diffs, highlighted off the main thread, that keep their place

- Status: accepted
- Date: 2026-10-19

## Context

Diffs mounted in 400-row chunks that only grew (ADR-102): scrolling to the end of a 20 000-line file left 20 000 rows (about 80 000 nodes) in the DOM, and in the pull request's Code tab, where the viewer grew with its content, the chunk sentinel was always "visible", so every chunk mounted on its own. Only short untracked files had syntax colours, computed on the main thread. Leaving a review tab or the Changes pane (the dock unmounts the inactive pane) lost the scroll position and the open file, and the pull request diff was fetched again every time its page opened.

## Decision

- **Virtualized rows.** A review is one flat list of rows (`lib/diff-document.ts`: typed arrays pointing into each file's parsed lines). `lib/diff-window.ts` keeps row offsets (`RowLayout`: measured height when known, else an estimate: the line height read from a hidden one-line probe, so the phone's taller rows count, or a wrapped estimate from the line length and the measured character width) and picks the window to mount: the viewport plus 600 px each side, snapped to 16 rows, so a scroll re-renders only when it crosses a boundary (one rAF-throttled scroll handler, no observers per row). The content box keeps the whole height and the widest line's width, so the scrollbars never jump. With wrapping on, mounted rows are measured after render and the first visible row is kept in place (WebKit has no scroll anchoring).
- **Whole reviews.** The pull request's Code tab and the turn review pass every file (`files`): one scroll with a header per file (path, kind, counts, Copy), collapsible, and the header of the file in view pinned at the top and pushed out by the next one. The list above jumps to a file and follows the scroll; the file in view is the selected one (the turn review's per-file Undo follows it, and its confirmation names the path). Binary, omitted and unchanged files show one notice row. The Changes pane and the guide still show one file.
- **Comments, find, keyboard.** Comment ranges are line indexes within one file, so they survive rows unmounting; Shift-click and Shift+↑/↓ extend within that file. Find (⌘F) searches every row of the expanded files and scrolls the current match into view, centred when it was off screen. On a line button or file header ↑/↓ move to the next focusable row (mounting and scrolling it first), Alt+↑/↓ jump between files, Enter/Space toggles a header. Guide anchors scroll as before.
- **Colours in a web worker.** `lib/code-tokens.ts` is the code block's highlighter, now shared; the diff uses its classes, so colours match in both themes. Each file's lines are cut into segments (each hunk, at most 400 lines); the viewer asks for the segments in its window, the file at the top first, plus two beyond each edge; `DiffHighlighter` runs one job at a time in `diff-highlight.worker.ts` and replaces its queue on every request, so scrolling away drops stale work. A segment tokenizes its old and new sides as source text, so multi-line comments and strings colour correctly. Rows show plain text until their segment arrives; results live in a WeakMap keyed by the parsed lines, so they last exactly as long as the parsed diff. Without Worker support (server rendering, tests) or after a worker error, diffs stay plain. Only source extensions are coloured. The untracked-file code block is gone: untracked files are coloured rows like any other.
- **Caches.** Parsed diffs are cached by their text (`lib/diff-cache.ts`: 96 entries or 24 MB of text, least recently used first). A pull request's diff is cached per repository, number and head commit (8 entries, 32 MB), so reopening the pull request or its Code tab does not fetch it again until the head moves.
- **Each tab keeps its place.** `lib/diff-view-state.ts` remembers, per view (turn review, pull request, Changes file), the scroll position, collapsed files and the file in view (64 views, memory only). A turn review reopened on a different file starts at that file instead. The Changes pane reopens the file it had open for that session, and the pull request page reopens the detail tab it was left on.

## Consequences

- Measured on a synthetic review (50 files, 20 000 changed lines; and one 20 000-line file) by server-rendering the viewer: at the end of the large file the old viewer had 20 000 rows (8.7 MB of markup, 416–505 ms to render) against 80 rows (37 KB, 3–14 ms) now; opening it mounts 80 rows instead of 400; a 50-file review opens with 79 rows. Building the document and layout for 20 000 rows takes about 2 ms and choosing the window under 1 µs per scroll frame. Tokenizing a 400-line segment takes about 6 ms in the worker; the whole 20 000-line file would take about 120 ms, which is why only the window is asked for.
- Selecting text across more than the mounted rows (about a screen and a half beyond the viewport) is not possible; Copy on the header copies the whole file's diff.
- Find skips collapsed files.
- Remembered places are lost on restart.
