# ADR-130: Mac settings from the phone, auto-archive, auto-pull and About pages

**Status:** Accepted (2026-10-13); the archiving it describes is superseded by [ADR-173](ADR-173-conversation-archive-removed.md).

## Context

The phone settings sheet (ADR-124) only held choices that stay on the phone. The phone should also edit the computer's own settings (new threads, thread behavior, source control, agent behavior, maintenance) and have an About section with client storage, diagnostics, licenses, legal and the version. Several of those settings did not exist in Sirus Code yet.

## Decision

- **Mac settings on the phone.** The sheet gains a "Mac settings" group with five pages: New conversations, Conversation behavior, Source control, Agent behavior and Maintenance (`MobileMacSettings`). Each change goes through the store's `saveSettings`, so the Mac saves and validates it as it does for its own Settings window. Nothing changes while the Mac is out of reach. Every one of these settings is also on the Mac (General, Chat behavior, Git, Worktrees, Providers) with the same options and wording; the shared labels live in `orchestration-strings.ts`, the phone-only ones in `phone-settings-strings.ts`.
- **Live settings.** `save_settings` now emits `settings-changed` with the saved settings, and so does auto-archive. The Mac window and paired phones take it in (`onSettingsChanged` in `bindRealtime`) unless one of their own saves is still on its way, so a phone change shows on the Mac at once and the Mac's next save does not undo it.
- **Default permissions** (`defaultApproval`, default Full access, the behavior before). The composer's three modes with their own labels and lines. A new conversation starts on it when the provider offers it; otherwise it steps down to the next safer mode the provider has, never up (`defaultApprovalFor` in `composer-approval.ts`). A conversation still keeps the mode it last used, and every turn still carries its own mode (ADR-017); the setting is only the composer's starting point.
- **Default workspace.** The existing `defaultSessionWorkspace`, with the Worktrees page's wording (Ask every time, Current checkout, New worktree).
- **Auto-archive** (`autoArchiveMerged`, `autoArchiveInactiveDays`; both off). A native pass every five minutes (`auto_archive.rs`) archives conversations whose own pull request was merged, or that had no activity for N days (1–90; 3 when first turned on). Running, waiting (pending approval or question), pinned, snoozed, side-chat and team-worker conversations are never archived. Pull requests are looked up only for conversations in their own worktree (a checkout's branch is not the conversation's), at most four per pass and once per 30 minutes each, through the same `gh` lookup as the PR panel. With "Release the worktree when a session is archived" on, `worktree_cleanup::release_archived` runs as after a manual archive and keeps unsafe trees. Archiving hides the conversation and may remove its worktree, so both start off.
- **Automatically pull the default branch** (`gitAutoPull`, off). Every five minutes (`auto_pull.rs`), a project checkout is fast-forwarded (`merge --ff-only` on `origin/<branch>`) only when it is on origin's default branch, has no changes (untracked files included), no conversation running in it, no commits of its own and something new on origin. The tree is checked again right after the fetch. It never merges, rebases or touches a dirty tree. The fetch (`git::fetch_origin_branch`) is bounded to 30 s and refused under the same hook and network-helper rules as push and pull. `gitAutoFetch` had no timing to reuse (the Git page shows it as unavailable), so this has its own.
- **Start new worktrees from origin** (`worktreesFromOrigin`, on). A new isolated worktree (a new conversation or an agent-started one) fetches origin's default branch first and starts from that commit; without origin, with a refused or failed fetch, or for a shared worktree it starts from `HEAD` as before (`worktree::origin_commit`, `start_point`). The fetch runs before the data lock is taken. Team workers keep their coordinator's base.
- **Response streaming** (`responseStreaming`: `turn`, `paragraph` or `token`; default `token`, the behavior before). The transcript shows a streaming reply's text after the turn, by finished paragraphs or code blocks (text up to the last blank line outside a fence or the last closed fence; `finishedParagraphs`), or word by word with the steady pace and fade of ADR-119, which only apply to that mode. The Mac and the phone share `SessionPane`, so both follow it.
- **Agent browser access** (`agentBrowserAccess`, on). Off, the MCP child gets `SIRUS_BROWSER_TOOLS=0` and lists no `browser_*` tools, and the bridge refuses `browser_*` calls from agents kept running. Session tools, secrets and PR watch share that server and stay. The person's own browser pane is unaffected.
- **Maintenance.** The existing "Check for CLI updates" and "Continue interrupted conversations after a crash".
- **Archived search.** The phone's Archived page has a floating glass search at the bottom that filters by title, project and branch, every word, ignoring case and accents (`archivedMatches`).
- **About Sirus.** Rows for Client storage, Diagnostics, Open source licenses, Legal and Version, above the shell, this device and Disconnect. Pages open one level deeper inside the sheet (the sheet keeps a page stack). Client storage shows the pairing (kept until Disconnect, never cleared there), the phone's own preferences (Reset), messages waiting in the offline outbox (Discard, after a second tap), the app shell cache (Clear) and other small items (kept). Diagnostics shows the connection, the Mac's shell and Git, the app version, whether it runs from the Home Screen, the offline shell and alerts; nothing leaves the phone. The version and the runtime npm packages with their licenses are read from `package.json` and `node_modules` at build time (`scripts/app-about.ts`, Vite `define` `__SIRUS_ABOUT__`). Legal is a short page.

## Consequences

- Turning on the inactivity rule archives every old conversation that qualifies at the next pass.
- "Start from origin" adds a fetch (at most 30 s) before a new worktree appears; offline it falls back at once when the fetch fails.
- The phone's Thread settings sheet passes the same default to `composerApproval`, and its New conversation sheet preselects it through `defaultApprovalFor`, so a new conversation starts on the same mode on both.
- The licenses page lists npm runtime packages only; the Mac app's Rust crates are in `Cargo.lock`.
