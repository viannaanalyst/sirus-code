# ADR-129: Phone conversation

**Status:** Accepted (2026-10-13); the archiving it describes is superseded by [ADR-173](ADR-173-conversation-archive-removed.md).

## Context

The phone conversation (ADR-081, ADR-086, ADR-124) wrapped the Mac's `SessionPane` and `AgentComposer` and hid what did not fit with CSS: the composer still showed access mode, model, effort, the context meter and usage chips in a cramped row, the header had terminal and review buttons plus a "···" menu (Git, Files, project icon, rename, delete), Files walked one folder per page, and the terminal had a plain key row. A calmer layout fits better: a one-line composer pill that grows when used, a Thread settings sheet for model and options, one glass pill in the header for terminal, files and Git with menus, a tree for files and a terminal key row with sticky modifiers.

## Decision

- **Composer slot.** `components/phone-composer-slot.ts` is a React context the phone conversation provides; the shared `AgentComposer` reads it and, when present, renders the phone's "+" button and model button instead of its add menu, emoji/usage chips, access menu, context meter and `ModelSelector`, and uses the phone placeholder ("Ask the agent…"). The composer never imports phone code; the desktop leaves the context empty and is unchanged. Sending, steering, the queue, compact-and-send, attachments, dictation, approvals and questions are the same component as before, so the Working pill, the offline outbox and the queue controls keep working.
- **Pill and card.** `MobileChat` sets `data-composer="collapsed|expanded"`: collapsed (no focus, no draft, attachment or snippet, no menu or sheet open, not dictating) the card is one pill with "+", the field, mic and send (`styles/mobile-chat.css`, `display: contents` on the footer rows); otherwise the card shows the field above a row with "+" on the left and the model button, mic and send on the right. Losing focus waits 220 ms so a tap on the model button lands first.
- **"+" menu.** A small glass popover with Choose files and Photo library (browser pickers, `readPhoneFiles`, ADR-086). Skills, goal, planning, debugging and team stay on the Mac and in `/` commands.
- **Thread settings.** The model button (provider or model icon, model name, chevron) opens a sheet with Cancel / Thread settings / Done: one collapsible section per installed and enabled provider (`isProviderEnabled`) with the desktop picker's models (`pickerModelChoices`), a check on the chosen one, a Default tag for the app's default model and a favorite star (`toggleModelFavorite`, applied at once); then Options with Reasoning, Service tier (only when the model offers Fast) and Access (the desktop access menu's modes and descriptions), each a sub-list; a floating "Find a model" field filters every section. Choices wait in a draft and Done applies them with the composer's rules: a model or provider change goes through the same `onModelChange` → `setSessionModel` (native handoff), effort and Fast are saved per model in `modelExecution` (Cursor presets switch catalog entry, `chooseExecution`), access goes into the composer context per provider (planning drops on Full access). Model, reasoning and tier are locked while the agent works, as on the Mac. `lib/composer-approval.ts` now holds the approval rule both composers use.
- **Header.** Back, the title (a tap renames; delete stays on the Home swipe row) with project · branch, and one glass pill: terminal, files, Git. The "···" menu, project icon and new-session entries are gone from the phone conversation.
- **Git menu.** A glass popover under the pill: the branch with Clean / N changed, Commit (disabled with "Branch is up to date. No action needed." when there is nothing to commit, else opens the Review screen where the commit flow lives), Review changes, and More (the full Git screen).
- **Terminal menu.** Project scripts (Setup, On finish) run through `project_scripts_action` like the Mac (ADR-078: only in the conversation's isolated worktree, output above the composer); without saved scripts a disabled "No project scripts" row. Then one row per terminal ("Terminal 1 — Ready/Running · project") that opens the terminal screen on that tab, and Open new terminal.
- **Files.** One tree: a folder opens in place (chevron, folder icon, indentation), a file opens its preview; a floating glass "Search files" field uses the composer's `workspace_files` name search; a folder found by search opens in the tree with its parents.
- **Terminal keys.** esc, CMD and CTRL (sticky: armed until the next key, from the row or the phone keyboard, with a pressed look), tab, paste (`navigator.clipboard.readText`, hidden when missing), clear (Ctrl-L), arrows and | ~ /, plus a keyboard button that focuses or blurs xterm's input. CTRL makes control characters and modified arrows; CMD follows macOS line editing (← start, → end, delete to start, K clears). The header has a terminal switcher. `TERMINAL_KEYS` and `withTerminalModifier` live in `lib/mobile.ts`.

## Consequences

- The phone composer is the shared one with two slots, not a fork: behaviour stays in one place, at the cost of CSS that reflows its footer on phones.
- Notes: the subtitle shows the branch instead of the machine (there is one Mac); project scripts run as Sirus scripts (isolated worktree, status above the composer) rather than typed into a new terminal tab; the project icon editor is no longer reachable from the phone.
- Pure helpers (`lib/phone-chat.ts`, `lib/composer-approval.ts`, terminal modifiers) are tested in `tests/phone-chat.test.ts`.

## Addendum: Home gestures (2026-10-13)

- **Long press.** Holding a Home row for 450 ms without moving more than 10 px (`createLongPress` in `lib/phone-home.ts`; no iOS callout or selection, `navigator.vibrate` where it exists) dims the screen, lifts the row as an elevated pill and opens a glass menu next to it (`MobileRowMenu`), above the row when it would not fit below (`contextMenuTop`). Items in order (`rowMenuItems`): Copy conversation ID, Archive / Unarchive (or Return from snooze), Arrange conversations… (by last activity or by creation, kept per phone), Pin / Unpin, Rename, Auto-archive › Enabled / Disabled as a second overlapping card with a check, and Delete in red behind the existing confirm. A right click opens the same menu; the scrim or Escape closes it. Regenerate title is left out: there is no such action to reuse.
- **Per-conversation auto-archive.** `Session.autoArchiveDisabled` (Rust `auto_archive_disabled`, omitted when false, so old data loads) is set by `set_session_auto_archive`; `auto_archive.rs` skips those conversations.
- **Swipe.** The swipe shows round buttons with a small label underneath: the lifecycle step (Archive, Unarchive, Return) in an accent-filled circle and Snooze plain (`styles/mobile-home.css`); the rest lives in the long-press menu.
- **Choose project.** The dock's new-conversation button opens a sheet (`MobileChooseProject`): grip, centered title, an Add project row (ADR-131), the projects in the phone's project order with `ProjectGlyph`, bold name and a middle-truncated path (`shortProjectPath`), and a floating glass "Search projects" field (`searchProjects`). Picking one swaps the sheet for the new conversation with that project chosen.
- Tests: `tests/phone-home.test.ts`.

## Addendum: Thread settings, summary first (2026-10-13)

- The sheet opens on a summary (Cancel / Settings / OK): a card with the pending model (provider icon tile, name, "Provider · Default" or "Provider · switches agent" when the pending provider differs from the conversation's, `threadSettingsSummary`) and a Change pill, then Options with only the rows the selected model has (`threadSettingsOptions`: Reasoning when it has effort levels, Service tier when it offers Fast, Access when the provider has approval modes).
- Change slides in the model list: one group per enabled, installed provider with a left-aligned header, a check on the pending model, the Default tag and a floating glass "Find a model" field searching every provider. Reasoning, Service tier and Access each slide in a short list with a check and a one-line hint. Picking anything slides back to the summary.
- Favorites are gone from the phone sheet (no section, no stars); they stay on the Mac. Apply rules are unchanged: nothing applies until OK. Styles live in `styles/mobile-thread-settings.css`; tests in `tests/phone-chat.test.ts`.

## Addendum: one-line Home rows, elevated composer, recording bar (2026-10-13)

- **Home rows.** Each conversation is one line on the page, no card: the project's `ProjectGlyph` (16px, muted), the title (ellipsis) and the relative time. A working conversation shows a pulsing accent dot instead of the icon and its time in the accent; one that needs the person a warning dot; a failed one a danger dot (`rowIndicator` in `lib/mobile.ts`). Branch and provider leave the row (they show in the conversation header); screen readers still hear the project and state. Sections are small muted labels with a thin rule to the right (`mobile-home-section` in `styles/mobile-home.css`). Rows being one line everywhere, the swipe circles shrink to 34px and their names stay as the buttons' accessible labels rather than visible text.
- **Composer.** The phone's composer is an elevated pill with no visible border: a surface one step above the page (dark `#1e1e21`, light white) and a soft shadow; the animated rim and the mic's metal surface are not drawn on the phone. Send is muted while empty and fills with the accent once there is something to send. The desktop composer is unchanged.
- **Recording.** While dictating, the composer turns into one bar: ✕ (discards), a waveform, the elapsed time and a round accent ✓ that stops and puts the transcript in the composer for review (it does not send). Collapsed, the bar replaces the whole pill; with a draft, the text stays above it. It animates in and out and respects reduced motion. The waveform moves with CSS, without an audio-level probe, as on the Mac (ADR-027 addendum).
- Tests: `tests/mobile.test.ts`.

## Launch animation and Home entrance (2026-10-14)

The phone app opens with the owner's choice from the previews ("A2 · orbit that lands", `MobileLaunch.tsx`, `mobile-launch.css`). Two orbits breathe while a point of light circles the inner one. The light keeps circling while the app connects (at least 0.9 s, at most 6 s). Then it lands in the centre, a flash reveals the glyph, and the launch fades out as Home enters: the page settles from 97% and the section labels and rows rise one by one (40 ms apart, capped at 200 ms). It runs once per app start. Reduced motion skips both, and the glyph turns dark in the light theme.

## Two-line rows and list options (2026-10-14)

Home rows have two lines. The first line holds the provider's icon (with the working, needs-you or failed dot), the title and the age. The second line, muted, holds the project, the branch (shortened in the middle, left out when unknown or detached), the pull request number when the Mac already looked it up, and the computer only when several are paired (`rowDetails` in `src/lib/phone-home.ts`).

The dock's left button opens "List options" (`MobileListOptions.tsx`). Project and Computer (the latter only with several computers) each open a second glass card over the first, with "All projects" or "All computers" first and a check on the current choice. "See projects" opens the Projects page. The filter applies to every section and to search, and it is kept per phone in `phone-prefs` (`homeProject`, `homeComputer`). A filter whose project or computer is no longer known is ignored, not forgotten. Chips under the header show the active filters and clear them, and with a project filter the new-conversation button starts in that project.
