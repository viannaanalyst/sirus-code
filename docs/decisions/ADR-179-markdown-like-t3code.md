# ADR-179: Reply Markdown renders the way T3 Code does

**Status:** Accepted (2026-10-28).

## Context

Replies were drawn by our own Markdown parser (`parseChatMarkdown`, `parseChatInline`): a few block kinds, a hand-written inline scanner, and a streamed variant that settled blocks at blank lines. It covered the basics but not what agents write every day: nested lists with several paragraphs, fenced code inside list items, footnotes, autolinks, reference links, and GFM edge cases, and each gap was another special case in the parser. T3 Code (MIT) renders replies with `react-markdown`, `remark-gfm` and `remark-math` and a set of custom components, parses only the growing tail of a streamed reply, and colours code with the shared Pierre highlighter. The owner asked for the same look and behaviour.

## Decision

- **Pipeline** (`ChatMarkdown.tsx`, `lib/markdown-pipeline.ts`). `react-markdown` 10 with `remark-gfm` (tables, task lists, strikethrough, autolinks, footnotes), `remark-math` and `remark-breaks` (single line breaks stay line breaks, as agents write them). Raw HTML is not enabled: there is no `rehype-raw`, so HTML in a reply shows as text, as before, and the pipeline needs no sanitizer. Link and image targets pass `urlTransform`: web, `mailto:`, `tel:`, `file:` and scheme-less paths survive, `javascript:` and any other scheme are dropped, and `data:` stays only as a base64 raster image source.
- **Math keeps ADR-160's rules** (`lib/markdown-math.ts`). `remark-math` would turn any `$…$` into a formula, so a pass over each block escapes the `$` that fail Pandoc's rule (prices, shell variables) and turns `\(…\)` and `\[…\]` into `$$…$$`; code is never touched. `rehype-katex` is not used, because it imports KaTeX eagerly. Math nodes render through `MathFormula`, so KaTeX and its stylesheet still load on the first formula, with the same `trust: false` and size limits and the same fallback to the source.
- **Incremental blocks** (`lib/markdown-blocks.ts`; the idea is T3 Code's incremental Markdown). The reply is cut into top-level blocks at blank lines that cannot belong to something bigger: not inside a fenced code block, not inside `$$` or `\[` display math, and not before an indented line or the next item of the same list. All blocks but the last are settled: they keep the same string on every delta, `MarkdownBlock` is memoized on that string, so they are neither parsed by unified nor reconciled again. Only the tail is rescanned (from its start) and parsed. A doubtful case merges rather than splits, since a merged block parses exactly as the text would whole; text with carriage returns or Markdown reference definitions is one block. An unfinished last line that could become a list marker (`-`, `2.`) does not settle the list before it. Components are one module-level object and block wrappers have the same element type for every position, so nothing remounts per delta.
- **Components kept from before.** Web links go through `ChatLink` (chips for bare addresses, ADR-149), inline code that names a workspace file or a local address becomes a file link or link chip, local image and video links render through `ReplyMedia` (ADR-119) and open the gallery (ADR-085), https and base64 images open the gallery, `ChatImageSource` still replaces image sources for pull requests, file links keep the context menu and the phone's file opener, the streaming fade (ADR-119) marks the last prose text of the last block (`rehypeStreamTail` wraps it, `StreamFadeText` renders it), and the find-in-transcript view still shows the unformatted text. Fenced code in a reply is split out earlier by `parseTranscript` as before; fences that only the Markdown parser sees (inside list items, pull request bodies) render as the same `CodeBlock` (header, language, copy, collapse) or `MermaidDiagram` (lazy), and display math as `MathFormula`.
- **Highlighting** (`lib/code-highlight.ts`, `CodeBlock`). Code blocks colour their source with `@pierre/diffs`' shared highlighter (ADR-169) in its `highlights` mode (WASM lexers), loaded on the first block and not part of the main bundle, with the `pierre-dark` and `sirus-light` themes of the diff viewer. Results are cached per source, language and appearance; the colours follow the app's light or dark theme. While Pierre loads, for languages it does not know, for sources over 40,000 characters and during a search, the lightweight regex colours stay. A streaming block asks again only after its source has rested 160 ms.
- **Look** (`styles/chat-markdown.css`). Real elements instead of the old `div role="heading"` and flex lists: headings, native bullet and numbered lists with muted markers, drawn task boxes, a blockquote with a left rule, tables as the existing translucent card, inline code and links as before, all with the Glass tokens (ADR-167) and the code font setting.
- **Removed.** `parseChatMarkdown`, `parseChatInline` and `chat-markdown-stream.ts` with their tests; `chat-markdown.ts` keeps the link helpers (`fileReference`, `localMediaKind`, …).

## Consequences

- Four dependencies are added (`react-markdown`, `remark-gfm`, `remark-math`, `remark-breaks`, all MIT) with the `unified` family; their notices are in `THIRD-PARTY-NOTICES.md` and `public/licenses/markdown/`. They load with the transcript, not lazily.
- Replies now render what the old parser dropped: footnotes, reference links, headings with setext underlines, fenced code and tables inside lists, nested blockquotes.
- Highlighting still runs on the main thread: Pierre's worker pool renders files and diffs, not loose snippets, so a code block is tokenized by the shared highlighter, once per source, off the render path (after the first paint and debounced while it streams).
- A stray unclosed `$$` or `\[` makes the rest of that reply one block until it closes; the render stays correct, only the saving is lost.
- Tested in `tests/markdown-blocks.test.ts` (block boundaries, fences, lists, math, streamed equivalence at every cut, identity of settled blocks), `markdown-math.test.ts`, `markdown-pipeline.test.ts` (markup, raw HTML, URL rules, the fade marker); `verify-pr-body.mjs` follows the new heading and list markup.
