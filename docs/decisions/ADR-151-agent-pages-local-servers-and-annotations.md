# ADR-151: Agent-opened pages float over the conversation, local servers are found natively, and annotations attach a picture

**Status:** Accepted (2026-10-19).

## Context

An agent that opens or navigates a page in the Sirus browser only changed state: the page stayed in the right dock, hidden unless the person looked for it. The browser's empty state and the Environment card listed local servers only when a terminal or agent printed a localhost URL, so a server started by a script or before the session was invisible. Project scripts could not say which page they serve. Annotating an element appended its selector as plain text to the draft, so the agent got no picture of what was marked.

## Decision

- **Agent pages float over the conversation** (`AgentPagePlayer.tsx`, `lib/mini-player.ts`). The browser's `browser_open` and `browser_navigate` tools emit `browser-agent-page { sessionId, url }` after the page is set (`browser.rs`, `reveal_agent_page`; `about:blank` and refused schemes are not revealed). The store shows it in a 360 × 240 player at the conversation's bottom-right corner (`agentPageBySession`), above the composer (136 px inset). The player's title bar shows the page title, Open in panel (hides the player and opens the dock's Browser pane) and close; dragging it snaps to the nearest corner on release (`nearestCorner`, `clampPlayerPosition`, `cornerPosition`, `miniPlayerSize` shrinks to fit a narrow or short conversation).
- **The native view is reused.** The player's frame is measured with `useBrowserBounds`, the same hook the dock pane uses, so `browser_set_bounds` moves the existing WKWebView into the frame; moving the player re-sends the bounds through the hook's window-resize path. The player is hidden and its bounds cleared when the dock's Browser pane shows the session (`isDockBrowserShowing`), when the page is blank, a picture-in-picture window holds the tab, or the browser is closed, so the hook's usual occlusion rule parks the view.
- **The setting** `browserShowAgentPages` (default on, Settings → Chat behavior → Browser) turns the auto-show off. A project script's preview (below) always opens, since the person asked for it.
- **Local servers** (`local_servers.rs`, `lib/local-servers.ts`, `lib/use-local-servers.ts`). `local_servers_list { sessionId }` reads listening TCP sockets with one `lsof -nP -iTCP -sTCP:LISTEN -F pcn` probe, their working folders with `lsof -a -d cwd -p …`, and the process table with `ps`, cached for 3 s. A listener is listed when its folder is inside the session's worktree or the project folder (any owner), or when it holds a typical development port (3000–3010, 4000–4010, 4173–4179, 4200, 4321, 5000–5010, 5173–5180, 6006, 8000–8010, 8080–8090, 8787, 8888, 9000, 19000–19006). macOS services (ControlCenter, rapportd, …), the agent CLIs, and Sirus's own process are never listed. Listeners are marked `owned` when they descend from Sirus, which is the only kind the Stop button stops (the existing `local_server_action` rule). The list merges with the output scan (`mergeLocalServers`: one row per port, process names where native) and shows in the browser's empty state and the Environment card's row with the port and process name.
- **When it is read.** The hook scans only while its view is mounted: the browser's empty state, the Environment card's Local servers section, once on showing and again when a script run or a terminal start bumps `serverScanTick` (after 1.5 s, so the listener is up). Nothing polls.
- **Project script previews** (`project_scripts.rs`). `ProjectScripts` gains `previewUrl` and `openPreview`, edited in Edit project → Scripts. `previewUrl` must be a loopback http(s) URL with a port (`local_servers::loopback_url`: no credentials, no spaces, at most 512 bytes; the editor mirrors it with `isPreviewUrlValid`). When any script of the project starts and `openPreview` is on, `watch_preview` polls `responds` (a TCP connect to 127.0.0.1 or ::1 at 600 ms, every 1.5 s) for the run's limit plus 90 s, then emits `project-preview { sessionId, url }`; the window opens a tab with that address in the session's browser and shows it in the player.
- **Annotations with a screenshot** (`browser.rs`, `annotate_capture`, `lib/browser-annotation.ts`). Finishing an annotation calls `browser_annotate_capture`: a fixed script measures each marked element and the viewport (`measure()` on the overlay, which also restores the numbered markers onto their elements), the visible page is snapshotted with the markers, and the overlay is removed. The window crops the picture to the marked elements with 16 px padding (`annotationCropRect`, mapped from viewport CSS px to the image's pixels; `cropAnnotationPng`) and attaches two composer attachments instead of appending text: `annotation-<time>.png` (the crop) and `annotation-<time>.txt` (page URL, viewport and one numbered line per element: label and selector). The text file's content reaches the agent through the attachment's text. Nothing is appended to the draft any more.
- **Native validation.** The URL checks above are the only route for a script preview to reach the window. Element text stays capped (20 elements, 400 characters per selector, 300 per label), and measured numbers are finite and bounded.

## Consequences

- An agent's browsing is visible without opening the dock; the player can be dismissed or moved, and it never covers the dock.
- Local servers appear without the person doing anything, at the cost of a bounded `lsof` and `ps` probe while a view is open (3 s cache). Ports outside the dev list are shown only when the process works in this project or worktree.
- The Stop button now appears only for servers Sirus started. A server found only in scanned output (no native listener) is listed without Stop.
- A script's preview opens on every run of a script of that project that starts while `openPreview` is on, not once per session.
- The player positions the native view from the window's bounds hook, so it inherits its limits: a menu or dialog over the player parks the page until the menu closes.
- Annotations need the page to be measurable: a cross-origin iframe's elements are not in the page's DOM and cannot be annotated, as before.

## Addendum (2026-10-20): pages that do not load

A page that fails before it commits (server down, a redirect to a closed port such as a dev server whose auth URL names another port, no network) used to leave a blank tab. The tab now shows a small error page with the address that failed, the system's reason and Try again (`load_error_page` in `browser.rs`, loaded as an HTML string whose base URL is the failed address). Cancelled loads, downloads and allowlist refusals stay silent. Reloading such a tab requests the address again instead of reloading the string. Agent-taken takeover checks count only trusted input, so the agent's own synthetic Enter no longer interrupts its next action.
